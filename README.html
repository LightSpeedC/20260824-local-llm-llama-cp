実測した生成速度

用途モデルと設定速度
対話・下書きQwen3-4B-Instruct-2507 -ngl 99 -c 819256.5 tok/s
事実・コードgemma-4-E4B-it -ngl 99（reasoning）45.2 tok/s
用途限定Qwen3.5-9B -ngl 24 ＋KV量子化8.1 tok/s
用途限定gpt-oss-20b --n-cpu-moe 185.9 tok/s
速度で一本化しないこと。 Qwen3-4B は 1〜2秒で返るが、「量子化とは」の説明で量子力学と混同した誤答を出した。 日本語が自然なぶん気づきにくい。gemma-4-E4B は思考を経るため10秒前後かかるが、同じ問いに正確に答える。 対話は 4B、事実確認とコードは E4B と用途で切り替える。
予想外だったのは gemma-4-E4B。 ファイルは 4.95 GiB で 9B クラス扱いだったが、Per-Layer Embeddings の 2730 MiB が CPU 側に分離されるため、 GPU には 2868 MiB しか載らず 4B クラスに近い速度で動く。 サイズだけで仕分けると取りこぼすモデルがある。詳細は計画書の第10章。
VRAM を超えても、エラーではなく「5〜40倍遅くなる」形で現れる。 NVIDIAドライバが共有GPUメモリに逃がすため止まらない。 -ngl の付けすぎと、コンテキスト 16384 の指定がこれを起こす。8192 を上限として運用する。
