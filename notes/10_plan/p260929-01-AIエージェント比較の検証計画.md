## 1. 目的

Claude Code がこのPCで遅いのは、最初に送る量（約 60,000 トークン）が大きいためである。 そのうち**共通ルールだけで 41,320 トークン**ある（2026-09-29、gpt-oss-20b のトークナイザで実測）。 ルールを読ませない状態と、送る量が小さいエージェントで、どこまで使えるようになるかを確かめる。

## 2. 進め方

Claude Code の試験（手順 2・3・4・1）がすべて終わってから始める。順番は次のとおり。

| 順 | エージェント | ルールを読ませない方法 |
|---:|---|---|
| 1 | Claude Code（ルールなし） | `USERPROFILE`・`HOME` を `tmp/` の空のホームに向けて起動する。利用者の `CLAUDE.md`・メモリ・フックが読まれない |
| 2 | Pi | もともと共通ルールを読まない。同じ空のホームに設定を置く |
| 3 | OpenCode | 同上 |
| 4 | Codex CLI（ルールなし） | 空のホームに `.codex/config.toml` を置く。`AGENTS.md` は読むため、試験用の作業フォルダで動かす |
| 5 | Aider | もともと共通ルールを読まない |

- **試験は Claude Code と同じ**。README の h1 を読む／決めた 1 行を書く。1 問 15 分、時間切れは後で 1 時間で試し直す
- **モデルは、Claude Code の試験で書きに合格したものを使う**（gemma-4-E2B・Qwen3-4B-Instruct・Ministral-3B など。最終的な選定は試験の結果を見て決める）
- 最初に送った量（トークン数）を、llama-server のログから読んで記録する

> [!IMPORTANT]
> **空のホームにしても、プロジェクトの `AGENTS.md` とローカルルールは残る。** Codex CLI は `AGENTS.md` を読むので、そのぶんは送る量に入る。比べるときは、読まれたものを記録に残す。

## 3. 導入するもの

| エージェント | 入れ方 | 備考 |
|---|---|---|
| Pi | `npm install -g --ignore-scripts @earendil-works/pi-coding-agent` | Node.js 22.19 以上（手元は 26.8） |
| OpenCode | `npm install -g opencode-ai` |  |
| Codex CLI | `npm install -g @openai/codex` | llama-server が Responses API に応じるかを先に確かめる |
| Aider | uv を入れ、`uv tool install --python python3.12 aider-chat@latest` | ⚠ **要判断** uv と Python 3.12 が入る。共通ルールの「Python は使用しない」は AI エージェントのコマンド実行の話で、ツールとして入れるのは別と扱う |

どれもグローバルに入れる。ダウンロードを伴うため、入れる前に利用者の許可を取る。
