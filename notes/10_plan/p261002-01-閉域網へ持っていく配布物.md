## この文書の位置づけ

どのモデルとエージェントの組み合わせが動くかは[ローカルLLM で AI エージェントを使う — 試験結果](../01_research/r260929-01-AIエージェントの試験結果.md)にある。 本書は、その結果をもとに、閉域網の PC へ持っていく配布物の中身と作り方を決める。

## 1. 目的と持っていく先

ネットにつながらない別の PC へ、**ローカル LLM（llama.cpp）・Node.js・エージェント・試験スクリプト・モデル**をまとめて運び、そこで同じ試験を流せるようにする。 現地では何もダウンロードしない。

### 持っていく先の PC

| PC | CPU | GPU（ドライバ） | メモリ | 扱い |
|---|---|---|---:|---|
| PC-A | Core i7-1355U（10 コア） | Iris Xe（32.0.101.7085） | 32 GB | 本命。メモリを 2 枚にして UHD から Iris Xe の表示に変わった |
| PC-B | Core i7-1355U（10 コア） | Iris Xe（32.0.101.7085） | 32 GB | 本命。PC-A と同じ構成 |
| PC-C | Core i7-1185G7（4 コア） | Iris Xe（30.0.101.1338、2022 年） | 16 GB | 手を加えずに試す |

### 現地で測った速さ（gemma-4-E4B UD-Q3_K_XL、llama-bench）

| PC | 使う版 | 入力の処理（pp512） | 生成（tg64） |
|---|---|---:|---:|
| PC-A | Vulkan（Intel GPU） | 163 tok/s | 7.5 tok/s |
| PC-A | CPU だけ | 34 tok/s | 8.4 tok/s |
| PC-C | Vulkan（Intel GPU） | 129 tok/s | 2.4 tok/s |
| PC-C | CPU だけ | 68 tok/s | 7.0 tok/s |

- **Intel GPU は入力の処理を速くする**（PC-A で約 5 倍）。生成はメインメモリの速さで頭打ちになり、CPU とほぼ同じ
- PC-C の Intel GPU だけ生成が遅いのは、古いドライバのためとみている（CPU だけなら 7.0 tok/s 出る）
- 指示文が長い Claude Code は Intel GPU、短い Pi は PC-C では CPU だけのほうが速い見込み（ベンチからの見積もりで、試していない）

## 2. 持っていくもの

| 種類 | 中身 | 作り方 |
|---|---|---|
| llama.cpp | b11320 の Vulkan 版（Intel GPU）・CPU 版・CUDA 版（NVIDIA がある PC のため） | GitHub の公式リリースを展開したフォルダをそのままコピーする。exe は同じフォルダの DLL を使うので、フォルダの中身を分けない |
| Node.js | v26.10.0 の **zip 版と msi 版の両方** | zip 版はインストールも管理者の権限も要らない。msi 版は、インストールして使いたい PC のために添える |
| エージェント | Pi・OpenCode・Claude Code（**npm 版と単体の `claude.exe` の両方**） | こちらで zip 版 Node.js のフォルダの中に npm でインストールし、そのフォルダごと運ぶ。インストール時に取ってくる OS 用の実行ファイルも中に入った状態で運べる |
| モデル | gemma-4-E4B（Q4_K_M、5.0 GB）・gemma-4-E2B（Q4_K_M、3.2 GB）・Ministral-3-3B（Q4_K_M、2.0 GB）・gemma-4-12B-QAT（Q4_0、6.5 GB） | 差し替え用のテンプレートがあるもの（いまは Ministral-3-3B）は `.jinja` も一緒に運ぶ |
| 試験スクリプト | `tools/50_run/` の sum・読み書き・ベンチの試験 | 置き場所を引数と 1 つの設定で変えられるようにしてから運ぶ（第 3 章） |
| 起動用の cmd | エージェントとモデルの組み合わせごとの cmd | 第 4 章 |
| GPU ドライバ | Intel 第 11〜14 世代向け 32.0.101.7092（`gfx_win_101.7092.exe`） | Intel の公式サイトから取得済み。入れるかは現地で決める |

持っていかないもの: Aider（試験で、書いたプログラムを自分では実行しなかった）・Codex（試験は利用者が流していた）。

> [!IMPORTANT]
> **Claude Code は利用条件を確かめてから配る。** npm で公開されているが、ライセンスは Anthropic の利用条件に従う。社内の閉域網へ持ち込んで使ってよいかを、配る前に確かめる。

## 3. どこに置いても動く形にする

配布物は 1 つのフォルダにまとめ、**どのドライブ・どのフォルダに置いても動く**ようにする（`Y:\` の直下でも、`D:\llm\` の下でも）。 スクリプトと cmd は、自分の置き場所（`%~dp0`・`$PSScriptRoot`）から相対で全部を探す。

### 配布物のフォルダ構成

```text
<配布先>\
  bin\
    llama.cpp-b11320-vulkan\
    llama.cpp-b11320-cpu\
    llama.cpp-b11320-cuda\
    node\                  zip 版 Node.js。中に npm で入れたエージェント
    claude\                単体の claude.exe
  installers\
    node-v26.10.0-x64.msi
    gfx_win_101.7092.exe
  models\                  .gguf（既定の置き場。設定で別の場所にもできる）
  templates\               .jinja
  run\                     起動用の cmd（第 4 章）
  tools\                   試験スクリプト
  config.cmd               場所の設定（下の表）
  work\                    エージェントの作業フォルダ・空のホーム（実行時に作る）
  logs\                    試験の結果（実行時に作る）
```

### 場所を決め打ちしているところ（直す箇所）

いまの試験スクリプトで、場所をリテラルで書いているのは次のとおり。 これを **`config.cmd` の 1 か所**にまとめ、現地で違う場所（例: `C:\AI-models`）にあるときは、そこだけを書き換えればよい形にする。

| いまの値 | 使っているところ | 設定の名前 | 配布物での既定 |
|---|---|---|---|
| `C:\AI_Models` | `test-agents.ps1`・`test-cc-tools.ps1`・`test-aider-followup.ps1` の `-ModelDir` | `LLM_MODEL_DIR` | `<配布先>\models` |
| `W:/temp/llama-cp-sandbox` | エージェントの作業フォルダ（3 本とも） | `LLM_WORK_DIR` | `<配布先>\work` |
| `W:/temp/llama-cp-agent-home` | Pi・OpenCode の空のホーム（`test-agents.ps1`） | （`LLM_WORK_DIR` の下） | `<配布先>\work\agent-home` |
| `W:/temp/llama-cp-home` | Claude Code の空のホーム（`test-cc-tools.ps1`） | （`LLM_WORK_DIR` の下） | `<配布先>\work\cc-home` |
| `bin/llama.cpp` | llama-server の場所（`-LlamaDir`） | `LLM_BACKEND` | 自動（第 4 章） |
| `tools/50_run/templates` | 差し替え用のテンプレート | — | `<配布先>\templates` |
| PATH の `node`・`pi`・`opencode`・`claude` | エージェントの起動 | — | cmd の中で `<配布先>\bin\node` を PATH の先頭に足す |

引数で渡せば、その回だけ設定より優先する（いまの `-ModelDir` などと同じ）。

> [!WARNING]
> **作業フォルダは配布物の中でも、プロジェクトの git の外に置く。** 試験では、作業フォルダがリポジトリの中にあると、モデルがリポジトリの root を推測して本物のファイルを読みにいった。配布物は git のリポジトリではないので `<配布先>\work` でよいが、開発用のこの PC で流すときは今までどおり外に置く。

## 4. エージェントとモデルごとの起動用 cmd

ダブルクリックで、llama-server を立ててエージェントを開けるようにする。**エージェントとモデルの組み合わせごとに 1 本**を `run\` に置く。

| cmd の名前（例） | 中身 |
|---|---|
| `pi-gemma-4-E4B.cmd` | E4B で llama-server を立て、Pi をそれにつないで開く |
| `claude-gemma-4-E4B.cmd` | 同じく Claude Code（npm 版）。`claude-exe-…` は単体の `claude.exe` |
| `opencode-gemma-4-E4B.cmd` | 同じく OpenCode |
| `server-gemma-4-E4B.cmd` | llama-server だけを立てる（エージェントを自分で開くとき） |

エージェント 3 つ（Claude Code は npm 版と単体版）× モデル 4 本。cmd は手で書かず、モデルとエージェントの一覧から生成する。

### cmd がすること

1. `config.cmd` を読む（モデルの場所など）
2. llama.cpp の版を選ぶ。`LLM_BACKEND` が空なら、Vulkan 版の `--list-devices` に GPU が出れば Vulkan 版、出なければ CPU 版
3. llama-server を立てる。オプションは試験と同じ（`-c 65536 -np 1 -fa on -ctk q8_0 -ctv q8_0 --reasoning off`、テンプレートがあれば `--chat-template-file`）
4. エージェントの接続設定を `work\` の下の空のホームに書き、そのホームでエージェントを開く（利用者のいつもの設定には触れない）

Intel GPU でのオプションの確かめ（`-fa`・`-ctk q8_0` が効くか、`-ngl`）は、この PC の Iris Xe では試験と同じオプションで動いた。現地でも同じ値から始める。

## 5. 作業の手順と未確認のこと

### 手順

1. 試験スクリプトの場所を `config.cmd` の設定と引数で変えられるようにする（第 3 章の表の箇所）
2. zip 版 Node.js を展開し、その中に Pi・OpenCode・Claude Code を npm で入れる。インストール時のスクリプトを止めずに入れ、OS 用の実行ファイルまでそろえる
3. 起動用の cmd を生成するスクリプトを書く
4. 配布物を組み立てるスクリプトを `tools/60_release/` に書く。出力先は `_releases/`
5. この PC で、配布物を別のドライブ（例: `Y:\`）に置き、ネットを切った状態で cmd と試験が動くかを確かめる
6. 現地で `--list-devices`・`llama-bench`・sum の試験を流す

### 未確認のこと

- **未** npm でインストールしたフォルダを、別の PC・別のドライブへ移しても動くか（中に絶対パスを持つものがないか）
- **未** Claude Code・OpenCode が、閉域網で更新の確認やログインをしようとして止まらないか
- **未** Claude Code を社内の閉域網で使ってよいか（利用条件）
- **未** PC-C の Intel GPU で生成が遅いのが、本当にドライバのためか（ドライバを入れるかは現地で決める）
