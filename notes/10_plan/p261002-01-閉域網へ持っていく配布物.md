## 1. 目的と持っていく先

ネットにつながらない別の PC へ、**ローカル LLM（llama.cpp）・Node.js・エージェント・試験スクリプト・モデル**をまとめて運び、そこで同じ試験を流せるようにする。 現地では何もダウンロードしない。

### 持っていく先の PC

| PC | CPU | GPU（ドライバ） | メモリ | 扱い |
|---|---|---|---:|---|
| PC-A | Core i7-1355U（10 コア） | Iris Xe（32.0.101.7085） | 32 GB | 本命。メモリを 2 枚にして UHD から Iris Xe の表示に変わった |
| PC-B | Core i7-1355U（10 コア） | Iris Xe（32.0.101.7085） | 32 GB | 本命。PC-A と同じ構成 |
| PC-C | Core i7-1185G7（4 コア） | Iris Xe（30.0.101.1338、2022 年） | 16 GB | 手を加えずに試す |

### 現地で測った速さ（gemma-4-E4B UD-Q3_K_XL、llama-bench）

| PC | 使う版 | 入力の処理（pp512） | 生成（tg64） |
|---|---|---:|---:|
| PC-A | Vulkan（Intel GPU） | 163 tok/s | 7.5 tok/s |
| PC-A | CPU だけ | 34 tok/s | 8.4 tok/s |
| PC-C | Vulkan（Intel GPU） | 129 tok/s | 2.4 tok/s |
| PC-C | CPU だけ | 68 tok/s | 7.0 tok/s |

- **Intel GPU は入力の処理を速くする**（PC-A で約 5 倍）。生成はメインメモリの速さで頭打ちになり、CPU とほぼ同じ
- PC-C の Intel GPU だけ生成が遅いのは、古いドライバのためとみている（CPU だけなら 7.0 tok/s 出る）
- 指示文が長い Claude Code は Intel GPU、短い Pi は PC-C では CPU だけのほうが速い見込み（ベンチからの見積もりで、試していない）

## 3. どこに置いても動く形にする

配布物は 1 つのフォルダにまとめ、**どのドライブ・どのフォルダに置いても動く**ようにする（`Y:\` の直下でも、`D:\llm\` の下でも）。 スクリプトと cmd は、自分の置き場所（`%~dp0`・`$PSScriptRoot`）から相対で全部を探す。

### 配布物のフォルダ構成

```text
<配布先>\
  bin\
    llama.cpp-b12359-vulkan\
    llama.cpp-b12359-cpu\
    llama.cpp-b12359-cuda\
    node\                  zip 版 Node.js。中に npm で入れたエージェント
    claude\                単体の claude.exe
    bun\                   bun
  installers\
    node-v26.13.1-x64.msi  （Intel GPU ドライバは入れず、_releases/drivers に別に置く）
  models\                  .gguf（既定の置き場。設定で別の場所にもできる）
  run\                     起動用の cmd（第 4 章）
  tools\50_run\            試験スクリプト・起動用の start-agent.ps1・paths.ps1
    templates\             .jinja
  .claude\settings.json    試験が作業フォルダに置く設定
  README.html              このプロジェクトの README（試験が作業フォルダにも写す）
  notes\                   資料（html と画像）。元の階層のまま写すので、README からのリンクが切れない
  config.cmd               場所の設定（下の表）
  使い方.html              現地での手順（持っていくもの・設定・動かす順番・試験・うまく動かないとき）
  work\                    エージェントの作業フォルダ・空のホーム（実行時に作る）
  logs\                    試験の結果（実行時に作る）
```

### 場所を決め打ちしているところ（直す箇所）

いまの試験スクリプトで、場所をリテラルで書いているのは次のとおり。 これを **`config.cmd` の 1 か所**にまとめ、現地で違う場所（例: `C:\AI-models`）にあるときは、そこだけを書き換えればよい形にする。

| いまの値 | 使っているところ | 設定の名前 | 配布物での既定 |
|---|---|---|---|
| `C:\AI-models` | `test-agents.ps1`・`test-cc-tools.ps1`・`test-aider-followup.ps1` の `-ModelDir` | `LLM_MODEL_DIR` | `<配布先>\models` |
| `W:/temp/llama-cp-sandbox` | エージェントの作業フォルダ（3 本とも） | `LLM_WORK_DIR` | `<配布先>\work` |
| `W:/temp/llama-cp-agent-home` | Pi・OpenCode の空のホーム（`test-agents.ps1`） | （`LLM_WORK_DIR` の下） | `<配布先>\work\agent-home` |
| `W:/temp/llama-cp-home` | Claude Code の空のホーム（`test-cc-tools.ps1`） | （`LLM_WORK_DIR` の下） | `<配布先>\work\cc-home` |
| `bin/llama.cpp` | llama-server の場所（`-LlamaDir`） | `LLM_BACKEND` | 自動（第 4 章） |
| `11434` | llama-server のポート（`start-agent.ps1` と試験 3 本の `-Port`） | `LLM_PORT` | `11434`（使用中なら起動前に止まる） |
| `tools/50_run/templates` | 差し替え用のテンプレート | — | `<配布先>\tools\50_run\templates`（スクリプトの置き場所からの相対なので、そのまま） |
| PATH の `node`・`pi`・`opencode`・`claude` | エージェントの起動 | — | cmd の中で `<配布先>\bin\node` を PATH の先頭に足す |

引数で渡せば、その回だけ設定より優先する（いまの `-ModelDir` などと同じ）。

読み込みは `tools/50_run/paths.ps1` が受け持つ。root に `config.cmd` があればその `set` 行を読み、無ければ環境変数、それも無ければ開発用の PC の場所（上の表の「いまの値」）にする。 開発用の PC には `config.cmd` を置かないので、今までどおりの場所で動く。

> [!WARNING]
> **作業フォルダは配布物の中でも、プロジェクトの git の外に置く。** 試験では、作業フォルダがリポジトリの中にあると、モデルがリポジトリの root を推測して本物のファイルを読みにいった。配布物は git のリポジトリではないので `<配布先>\work` でよいが、開発用のこの PC で流すときは今までどおり外に置く。

## 4. エージェントとモデルごとの起動用 cmd

ダブルクリックで、llama-server を立ててエージェントを開けるようにする。**エージェントとモデルの組み合わせごとに 1 本**を `run\` に置く。

| cmd の名前（例） | 中身 |
|---|---|
| `pi-gemma-4-E4B.cmd` | E4B で llama-server を立て、Pi をそれにつないで開く |
| `claude-gemma-4-E4B.cmd` | 同じく Claude Code（npm 版）。`claude-exe-…` は単体の `claude.exe` |
| `opencode-gemma-4-E4B.cmd` | 同じく OpenCode |
| `server-gemma-4-E4B.cmd` | llama-server だけを立てる（エージェントを自分で開くとき） |
| `bench-gemma-4-E4B.cmd` | Vulkan 版（Intel GPU）と CPU 版で、llama-bench の速さを測る |
| `list-devices.cmd` | Vulkan 版から見える GPU を表示する（1 本だけ） |

モデル 7 本 × 6 種類（Pi・OpenCode・Claude Code の npm 版と単体版・サーバだけ・速さ）＋ `list-devices.cmd` の 43 本。cmd は手で書かず、組み立てのスクリプトがモデルの一覧から生成する。中身はどれも `tools\50_run\start-agent.ps1` を引数付きで呼ぶだけ。

これとは別に、`tools\50_run\start-agent.cmd` を引数なしで叩くと、エージェントとモデルを一覧から選んで起動できる（p261113-01 の決定 2-A）。使い方は `tools\50_run\使い方.html`。

### cmd がすること

1. `config.cmd` を読む（モデルの場所など）
2. llama.cpp の版を選ぶ。`LLM_BACKEND` が空なら、Vulkan 版の `--list-devices` に GPU が出れば Vulkan 版、出なければ CPU 版
3. ポート（`LLM_PORT`、既定 11434）が空いているかを見る。使用中なら、使っているプログラム名を出して止める
4. llama-server を立てる。オプションは試験と同じ（`-c 65536 -np 1 -fa on -ctk q8_0 -ctv q8_0 --reasoning off`、テンプレートがあれば `--chat-template-file`）
5. エージェントの接続設定を `work\` の下の空のホームに書き、そのホームでエージェントを開く（利用者のいつもの設定には触れない）

Intel GPU でのオプションの確かめ（`-fa`・`-ctk q8_0` が効くか、`-ngl`）は、この PC の Iris Xe では試験と同じオプションで動いた。現地でも同じ値から始める。

## 5. 作業の手順と未確認のこと

### 手順

- ✅ **済** 試験スクリプトの場所を `config.cmd` の設定と引数で変えられるようにする（`tools/50_run/paths.ps1`）
- ✅ **済** zip 版 Node.js（SHA256 を照合）を展開し、その中に Claude Code 2.1.287・Pi 0.99.2・OpenCode 1.18.34 を npm で入れる（2026-10-02 の版。いまは Claude Code 2.1.325・Pi 1.5.2・OpenCode 1.19.5）
- ✅ **済** 起動用の `tools/50_run/start-agent.ps1` を書き、組み立てのときに組み合わせごとの cmd を生成する
- ✅ **済** 配布物を組み立てる `tools/60_release/make-offline-bundle.ps1` を書く。出力は `_releases/offline/llm-bundle-yyyyMMdd`（2026-10-02 の版はモデル込みで 20.4 GB。いまはツール類を 1 つの 7z〔約 1.0 GB〕、モデルを 1 本ずつ別の 7z〔7 本で約 39 GB、`_releases/models-20261016`〕に分ける）
- ✅ **済** この PC で、配布物をプロジェクトの外の別の場所に置き、`config.cmd` のモデルの場所を書き換えて動くかを確かめる（下の表）
- ✅ **済** 現地での手順を `tools/60_release/bundle/使い方.html` に書き、配布物の root に入れる。手順のとおりに配布物の中で `test-agents.cmd` を流し、PATH を足さずに配布物の node が使われ、Vulkan 版が自動で選ばれることを確かめた
- ✅ **済** ツールとモデルを最新にして組み立て直す（2026-10-16 にモデル 7 本の 7z、2026-11-15 に llama.cpp b12359・Node.js v26.13.1・Claude Code 2.1.325・Pi 1.5.2・OpenCode 1.19.5・bun 1.4.4 のツール類 `llm-bundle-20261115.7z`）。7z を別の場所へ展開し、同梱の版が合うことを確かめた。展開しての試験は未（課題 i261014-01）
- ✅ **済** 新しい版（Claude Code 2.1.325・Pi 1.5.2・OpenCode 1.19.5）で、gemma-4-E4B の読み・書きを再試験する（2026-11-15・11-18。3 つとも合格。[試験結果](../01_research/r260929-01-AIエージェントの試験結果.md)の「最新版で流し直した結果」）
- ✅ **済** 新しい小型モデル 2 本（LFM3-1.7B・Nemotron-3.5-Bolt-E4B）を追加で試験する（2026-11-18。Bolt-E4B は Claude Code だけが読み・書きとも合格、LFM3-1.7B は Pi の読みだけ合格。配布するモデルには足していない。[試験結果](../01_research/r260929-01-AIエージェントの試験結果.md)の「新しい小型モデルの追加試験」）
- ⬜ **未** ネットを切った状態で動くかを確かめる
- ⬜ **未** 現地で `list-devices.cmd`・`bench-….cmd`・sum の試験を流し、対話の cmd で使ってみる

### 別の場所に置いて確かめた結果

配布物をプロジェクトの外へ写し（モデルは除く）、`config.cmd` の `LLM_MODEL_DIR` を開発用の PC のモデルの場所に書き換えて流した。 PATH は配布物の `bin\node` と Windows の最小限だけにし、この PC に入っている Node.js・エージェントを使わないようにした。

| 確かめたこと | 結果 |
|---|---|
| `list-devices.cmd` | ✅ Intel GPU（Vulkan0）が見えた |
| `bench-gemma-4-E2B….cmd` | ✅ 書き換えた場所からモデルを見つけ、Vulkan 版と CPU 版で測れた（この PC は NVIDIA もあるので、Vulkan 版の値は NVIDIA と合わせた速さ） |
| Pi の試験（E4B） | ✅ 日本語の確認・sum とも合格。版は配布物の pi 0.99.2・node v26.10.0 |
| Claude Code npm 版の試験（E4B） | ✅ 日本語の確認・sum とも合格 |
| Claude Code 単体版の試験（E4B） | ✅ sum 合格（`bin\claude` を PATH の先頭にして `claude.exe` を使わせた） |
| OpenCode の試験（E4B） | ✅ sum 合格 |
| 起動用の cmd（Pi・E2B） | ✅ Vulkan 版を自動で選び、サーバを立て、Pi を開き、閉じたらサーバを止めた（入力をつながなかったので Pi はすぐ終わった。対話はまだ試していない） |
| 開発用の PC での試験 | ✅ `config.cmd` なしで、今までの場所のまま動いた |

試験は速さを見るものではないため、サーバは CUDA 版で動かした。

> [!IMPORTANT]
> **配布物の Claude Code の版は、試験した版と合っているかを組み立てるたびに確かめる。** 2026-10-02 の組み立てでは、3 回ずつ流した試験は 2.1.286 で、npm の版が自動で上がっていたため配布物には 2.1.287 を入れた。2026-11-15 の組み立ては 2.1.325 で、E4B の読み・書きを同じ版で流して合格している。
