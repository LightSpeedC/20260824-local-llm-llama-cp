AI エージェント比較の検証計画

Claude Code（ルールなし）・Pi・OpenCode・Codex CLI（ルールなし）・Aider を、同じ試験で llama-server に繋いで比べる

この文書の位置づけ

事前調査は Claude Code 以外の AI エージェント調査。

目的

Claude Code がこのPCで遅いのは、最初に送る量（約 60,000 トークン）が大きいためである。 そのうち共通ルールだけで 41,320 トークンある（2026-09-29、gpt-oss-20b のトークナイザで実測）。 ルールを読ませない状態と、送る量が小さいエージェントで、どこまで使えるようになるかを確かめる。

進め方

Claude Code の試験（手順 2・3・4・1）がすべて終わってから始める。順番は次のとおり。

順エージェントルールを読ませない方法
1Claude Code（ルールなし）USERPROFILE・HOME を tmp/ の空のホームに向けて起動する。利用者の CLAUDE.md・メモリ・フックが読まれない
2Piもともと共通ルールを読まない。同じ空のホームに設定を置く
3OpenCode同上
4Codex CLI（ルールなし）空のホームに .codex/config.toml を置く。AGENTS.md は読むため、試験用の作業フォルダで動かす
5Aiderもともと共通ルールを読まない
  • 試験は Claude Code と同じ。README の h1 を読む／決めた 1 行を書く。1 問 15 分、時間切れは後で 1 時間で試し直す
  • モデルは、Claude Code の試験で書きに合格したものを使う（gemma-4-E2B・Qwen3-4B-Instruct・Ministral-3B など。最終的な選定は試験の結果を見て決める）
  • 最初に送った量（トークン数）を、llama-server のログから読んで記録する
空のホームにしても、プロジェクトの AGENTS.md とローカルルールは残る。 Codex CLI は AGENTS.md を読むので、そのぶんは送る量に入る。比べるときは、読まれたものを記録に残す。

導入するもの

エージェント入れ方備考
Pinpm install -g --ignore-scripts @earendil-works/pi-coding-agentNode.js 22.19 以上（手元は 26.8）
OpenCodenpm install -g opencode-ai
Codex CLInpm install -g @openai/codexllama-server が Responses API に応じるかを先に確かめる
Aideruv を入れ、uv tool install --python python3.12 aider-chat@latest要判断uv と Python 3.12 が入る。共通ルールの「Python は使用しない」は AI エージェントのコマンド実行の話で、ツールとして入れるのは別と扱う

どれもグローバルに入れる。ダウンロードを伴うため、入れる前に利用者の許可を取る。

結果（2026-09-30）

  • 5 つとも試し終えた。結果は Claude Code のツール利用テストの第 5・6 章
  • Claude Code（ルールなし）：思考を切ると 20 本中 15 本が 15 分以内に読み・書きとも合格。root の cc1.cmd をこの設定で作り直した
  • Pi：Claude Code で通らなかった Nemotron-4B が 18 秒で合格。もっとも速い
  • OpenCode：Nemotron-4B は合格、GLM-4.6V は書きのみ
  • Codex CLI（ルールなし）：gpt-oss-20b が合格。Windows では安全装置を外さないとファイルを読み書きできない
  • Aider：ファイルを先に渡す道具なので、読みの問は成り立たない。書きは通る。試験中にプロジェクトの README.html を上書きしたため、以後の試験はすべて作業用のコピーで動かした

計画からの変更: 作業フォルダとホームは tmp/ ではなく W:/temp の下に置いた（プロジェクトの中に置くと、モデルがプロジェクトの場所を推測して本物に読み書きしにいくため）。
