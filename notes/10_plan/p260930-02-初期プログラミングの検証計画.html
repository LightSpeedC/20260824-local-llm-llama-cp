目的と対象

ファイルを 1 行書けたモデルとエージェントが、日本語の指示で、プログラムを書く → 実行する → 結果を答えるところまでできるかを確かめる。

問と判定

問

日本語の原文のまま渡す。

1から10までの合計を表示するnode.jsプログラムをsum.jsに書く。node sumで実行する

コマンド行の日本語は、試験スクリプトと同じ渡し方（Windows PowerShell 5.1 → cmd.exe → npm の cmd の起動口 → node）で、化けずに届くことを確かめてある（2026-09-30）。

判定

エージェントが終わったあと、試験スクリプトが作業用のコピーの中で次を確かめる。

段見ること合格の条件
① 作成sum.js ができたかファイルがある
② 動作試験スクリプト自身が node sum を実行する標準出力に 55 という数がある（ほかの数字とつながっていない）。「1から10までの合計: 55」のような表示も正しいものとする
③ 報告エージェントの答え55 を含む
④ 中身sum.js のソースログに残して目で見る。console.log(55) のような決め打ちでないか
⑤ 実行の跡エージェントの作業ログ道具の呼び出しに node sum がある
  • ①②③がそろって合格。①②だけなら「書けたが報告なし」、③だけなら「実行せずに答えた疑い」として分けて記録する
  • ⑤は、エージェントが自分で node を実行したかを見るためのもの。合否には入れず、③で 55 と答えたのが実行した結果か、暗算かを分けるのに使う

作業ログの取り方

エージェント取り方
Claude Code--output-format stream-json --verbose。道具の呼び出しが 1 行ずつ出る
Pi--no-session の代わりに --session-dir を渡し、セッションのファイルを読む
OpenCode--format json。答えの文は JSON の出来事から拾う

Claude Code には node の実行だけを許す。 試験は --permission-mode acceptEdits で動かしており、許されるのはファイルの編集だけで、コマンドの実行は止められる。 sum の問では --allowedTools "Bash(node:*)" を足し、node で始まるコマンドだけを許す。書く・実行する・答えるで手数が増えるため、--max-turns も 6 から 10 にする。

簡易サンドボックスと流し方

簡易サンドボックス

  • どのエージェントも、プロジェクトの外にあるコピー（W:/temp/llama-cp-sandbox）の中で動かす
  • 1 問ごとにコピーを作り直し、sum.js が無い状態から始める
  • Claude Code は、これまでどおりホームも W:/temp の下の空のフォルダにする
  • 判定の node sum も、試験スクリプトがこのコピーの中で実行する
簡易サンドボックスは、作業フォルダを分けるだけで、外への書き込みは止めない。 エージェントがコピーの外のパスを推測して書きにいけば届く。 読み書きの試験では、ホームがプロジェクトの中にあった回に、プロジェクトの本物のファイルへ読み書きしにいった（試験結果の第 5 章）。

流し方

  1. 確認用の 1 問。gemma-4-E4B を 4 つのエージェントで動かし、「次の日本語をそのまま繰り返して」と頼んで、化けずに返るかを見る（-Tests echo）。化けたエージェントは、問をファイルに書いて標準入力から渡す形に切り替える
  2. 本番。エージェントごとに、19 本のモデルを速いものから順に流す（-Tests sum）。試験スクリプトはモデルごとに llama-server を立て直す。サーバの設定は読み書きの試験と同じ（思考なし・差し替えたテンプレートがあるモデルはそれを使う）
  3. Codex。本番のあと、利用者がコマンドを実行する

結果は 1 件終わるごとに logs/ に書き出し、そのつど報告する（ローカルルール「長い試験・測定の進め方」）。

作業の手順

  1. tools\50_run\test-agents.ps1 と tools\50_run\test-cc-tools.ps1 の -Tests に sum と echo を足す。既定は read,write（これまでの読み書き）のまま。判定は tools\50_run\sum-judge.ps1 に 1 つだけ書き、両方から読み込む
  2. test-agents.ps1 のコメント「コマンド行に日本語を載せると CP932 に化ける」を、確かめた事実に直す
  3. 確認用の 1 問を流す
  4. 本番の 76 回を流す
  5. 結果を試験結果に 1 章として足し、全実行の記録に行を足す
  6. 課題 i260930-05 の状態を進める

未確認のこと

  • 未確認OpenCode・Codex に日本語が届くか。どちらも node ではなくネイティブの exe を起動する。同じ仕組みで届くはずだが、実物では確かめていない（第 3 章の確認用の 1 問で見る）
  • 未確認Aider が node sum まで実行するか。Aider は編集のあとにシェルのコマンドを提案し、--yes-always ならそのまま実行するはず。実行しなければ①②は通っても③で落ちる
  • 未確認各エージェントがどのシェルで node を呼ぶか（Git Bash・PowerShell・cmd）。node が PATH にあれば、どれでも動くはず
