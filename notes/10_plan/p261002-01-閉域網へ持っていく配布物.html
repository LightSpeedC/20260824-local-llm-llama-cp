この文書の位置づけ

どのモデルとエージェントの組み合わせが動くかはローカルLLM で AI エージェントを使う — 試験結果にある。 本書は、その結果をもとに、閉域網の PC へ持っていく配布物の中身と作り方を決める。

目的と持っていく先

ネットにつながらない別の PC へ、ローカル LLM（llama.cpp）・Node.js・エージェント・試験スクリプト・モデルをまとめて運び、そこで同じ試験を流せるようにする。 現地では何もダウンロードしない。

  • Intel GPU は入力の処理を速くする（PC-A で約 5 倍）。生成はメインメモリの速さで頭打ちになり、CPU とほぼ同じ
  • PC-C の Intel GPU だけ生成が遅いのは、古いドライバのためとみている（CPU だけなら 7.0 tok/s 出る）
  • 指示文が長い Claude Code は Intel GPU、短い Pi は PC-C では CPU だけのほうが速い見込み（ベンチからの見積もりで、試していない）

どこに置いても動く形にする

配布物は 1 つのフォルダにまとめ、どのドライブ・どのフォルダに置いても動くようにする（Y:\ の直下でも、D:\llm\ の下でも）。 スクリプトと cmd は、自分の置き場所（%~dp0・$PSScriptRoot）から相対で全部を探す。

読み込みは tools/50_run/paths.ps1 が受け持つ。root に config.cmd があればその set 行を読み、無ければ環境変数、それも無ければ開発用の PC の場所（上の表の「いまの値」）にする。 開発用の PC には config.cmd を置かないので、今までどおりの場所で動く。

作業フォルダは配布物の中でも、プロジェクトの git の外に置く。 試験では、作業フォルダがリポジトリの中にあると、モデルがリポジトリの root を推測して本物のファイルを読みにいった。配布物は git のリポジトリではないので <配布先>\work でよいが、開発用のこの PC で流すときは今までどおり外に置く。

エージェントとモデルごとの起動用 cmd

ダブルクリックで、llama-server を立ててエージェントを開けるようにする。エージェントとモデルの組み合わせごとに 1 本を run\ に置く。

cmd の名前（例）中身
pi-gemma-4-E4B.cmdE4B で llama-server を立て、Pi をそれにつないで開く
claude-gemma-4-E4B.cmd同じく Claude Code（npm 版）。claude-exe-… は単体の claude.exe
opencode-gemma-4-E4B.cmd同じく OpenCode
server-gemma-4-E4B.cmdllama-server だけを立てる（エージェントを自分で開くとき）
bench-gemma-4-E4B.cmdVulkan 版（Intel GPU）と CPU 版で、llama-bench の速さを測る
list-devices.cmdVulkan 版から見える GPU を表示する（1 本だけ）

モデル 4 本 × 6 種類（Pi・OpenCode・Claude Code の npm 版と単体版・サーバだけ・速さ）＋ list-devices.cmd の 25 本。cmd は手で書かず、組み立てのスクリプトがモデルの一覧から生成する。中身はどれも tools\50_run\start-agent.ps1 を引数付きで呼ぶだけ。

cmd がすること

  1. config.cmd を読む（モデルの場所など）
  2. llama.cpp の版を選ぶ。LLM_BACKEND が空なら、Vulkan 版の --list-devices に GPU が出れば Vulkan 版、出なければ CPU 版
  3. llama-server を立てる。オプションは試験と同じ（-c 65536 -np 1 -fa on -ctk q8_0 -ctv q8_0 --reasoning off、テンプレートがあれば --chat-template-file）
  4. エージェントの接続設定を work\ の下の空のホームに書き、そのホームでエージェントを開く（利用者のいつもの設定には触れない）

Intel GPU でのオプションの確かめ（-fa・-ctk q8_0 が効くか、-ngl）は、この PC の Iris Xe では試験と同じオプションで動いた。現地でも同じ値から始める。

作業の手順と未確認のこと

手順

  • 済試験スクリプトの場所を config.cmd の設定と引数で変えられるようにする（tools/50_run/paths.ps1）
  • 済zip 版 Node.js（SHA256 を照合）を展開し、その中に Claude Code 2.1.287・Pi 0.99.2・OpenCode 1.18.34 を npm で入れる
  • 済起動用の tools/50_run/start-agent.ps1 を書き、組み立てのときに組み合わせごとの cmd を生成する
  • 済配布物を組み立てる tools/60_release/make-offline-bundle.ps1 を書く。出力は _releases/offline/llm-bundle-yyyyMMdd（モデル込みで 20.4 GB）
  • 済この PC で、配布物をプロジェクトの外の別の場所に置き、config.cmd のモデルの場所を書き換えて動くかを確かめる（下の表）
  • 済現地での手順を tools/60_release/bundle/使い方.html に書き、配布物の root に入れる。手順のとおりに配布物の中で test-agents.cmd を流し、PATH を足さずに配布物の node が使われ、Vulkan 版が自動で選ばれることを確かめた
  • 未ネットを切った状態で動くかを確かめる
  • 未現地で list-devices.cmd・bench-….cmd・sum の試験を流し、対話の cmd で使ってみる

別の場所に置いて確かめた結果

配布物をプロジェクトの外へ写し（モデルは除く）、config.cmd の LLM_MODEL_DIR を開発用の PC のモデルの場所に書き換えて流した。 PATH は配布物の bin\node と Windows の最小限だけにし、この PC に入っている Node.js・エージェントを使わないようにした。

確かめたこと結果
list-devices.cmd✅ Intel GPU（Vulkan0）が見えた
bench-gemma-4-E2B….cmd✅ 書き換えた場所からモデルを見つけ、Vulkan 版と CPU 版で測れた（この PC は NVIDIA もあるので、Vulkan 版の値は NVIDIA と合わせた速さ）
Pi の試験（E4B）✅ 日本語の確認・sum とも合格。版は配布物の pi 0.99.2・node v26.10.0
Claude Code npm 版の試験（E4B）✅ 日本語の確認・sum とも合格
Claude Code 単体版の試験（E4B）✅ sum 合格（bin\claude を PATH の先頭にして claude.exe を使わせた）
OpenCode の試験（E4B）✅ sum 合格
起動用の cmd（Pi・E2B）✅ Vulkan 版を自動で選び、サーバを立て、Pi を開き、閉じたらサーバを止めた（入力をつながなかったので Pi はすぐ終わった。対話はまだ試していない）
開発用の PC での試験✅ config.cmd なしで、今までの場所のまま動いた

試験は速さを見るものではないため、サーバは CUDA 版で動かした。

Claude Code は試験のときより 1 つ新しい 2.1.287 を入れた。 3 回ずつ流した試験は 2.1.286 だった。npm の版が自動で上がっていたため、配布物にはいま入っている 2.1.287 を入れている。

未確認のこと

  • 未npm でインストールしたフォルダを、別の PC・別のドライブへ移しても動くか（中に絶対パスを持つものがないか）
  • 未Claude Code・OpenCode が、閉域網で更新の確認やログインをしようとして止まらないか
  • 未Claude Code を社内の閉域網で使ってよいか（利用条件）
  • 未PC-C の Intel GPU で生成が遅いのが、本当にドライバのためか（ドライバを入れるかは現地で決める）
