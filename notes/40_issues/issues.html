未i260927-02Speculative Decoding の検証

小さなドラフトモデルで先読みして生成を速める手法。本命とドラフトを同居させると VRAM の余裕は約 200 MiB と見積もっており、 帯域を使い切っている本PCでは効果が出ない可能性もある。

  • 未使用中のビルドの llama-server --help で、ドラフトモデル指定のオプション名を確かめる
  • 未本命と同系列のドラフトモデル（Qwen3-0.6B の GGUF）を取得する
  • 未調査の検証計画にある5構成を測り、結果を調査に反映する

着手i260927-05RAM 32GB を前提に結論を見直す

RAM を 32GB に増設し、画面表示を内蔵GPU に任せたところ、CPU 側に重みを置くモデルが大きく速くなった （Qwen3.5-9B 8.1 → 14.6 tok/s、gpt-oss-20b 5.9 → 19.0 tok/s）。KV を q8_0 にすればコンテキスト 16384 も使える。 実行計画の結論と方針は RAM 16GB の実測に基づいたままで、再測定と合わなくなっている。

  • 済RAM と VRAM に左右されるものを 32GB で測り直し、実行計画・調査に追記する
  • 済実行計画の結論と方針（gpt-oss-20b の位置づけ、コンテキストの上限）を見直す
  • 未gemma-4-E4B を測り直す（CPU 側に置く PLE が速くなる可能性がある）
  • 未Qwen3-30B-A3B（Q4_K_M・約 18 GB）を取得して測る
  • 済Claude Code 用のモデルを gpt-oss-20b で試す（25 分でタイムアウト。10GB 未満の 13 本も試し、ツール利用テストに記録）

済i260927-03Claude Code の接続先を llama-server へ切り替える

これまで LM Studio に向けていた接続先を、llama-server（127.0.0.1:8080）へ切り替える。 llama-server は Anthropic 形式の /v1/messages に直接応答するため、変換の層を挟まずに繋がる。

Claude Code は最初の要求だけで約 63,000 トークンある。VRAM 4GB には KV キャッシュが載らないため、 コンテキスト 65536・KV キャッシュを RAM 側（-nkvo）・q8_0 で起動する。 初回は 157 秒かかるが、2回目以降は共通部分が再利用されて 14 秒になる。

  • 済llama-server が Anthropic 形式に直接応答することを確かめる
  • 済サーバの起動（tools/50_run/run-server-cc.cmd）と Claude Code の起動（root の cc1.cmd）をスクリプトにする
  • 済Claude Code から応答が返ることを確かめる
