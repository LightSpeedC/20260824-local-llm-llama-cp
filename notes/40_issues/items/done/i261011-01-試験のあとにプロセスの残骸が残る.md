title: 試験のあとにプロセスの残骸が残る
group: 運用
created: 2026-10-11
---

試験の見張りに使った `tail -f … | grep` が、見張りを止めても終わらずに残っていた。親のプロセスはすでに無く、`-f` で待ち続けるので、自然には終わらない。試験のたびに増えていく。

- [済] 残骸を止める（2026-10-11。10/01〜10/04 の tail 26 本・grep 26 本と、10/02 の aider の cmd 1 本。先祖のプロセスが無いため、コマンドラインで見分けた。tail は引数がこのプロジェクトのパス、grep は tail と同じ時刻に起動していて検索語が試験のもの、aider は出力先がこのプロジェクトの `logs/`。ほかのプロジェクトの tail・grep 各 1 本には触れていない）
- [済] 試験のあとに残骸を確かめて止める手順を、ローカルルールに書く（2026-10-11。「長い試験・測定の進め方」に 3 行足した）
- [済] Git for Windows の tail で `--pid` が効くか確かめる（2026-10-11。`tail -n 0 -f --pid=$$ … | grep …` を bash で起動して確かめた。`$$` が指す内側の bash（`usr/bin/bash.exe`）を止めると、tail はすぐ終わり、grep も入力が切れて終わった。外側の bash（`bin/bash.exe`）だけを止めても、内側が生きている間は tail も残る。残骸はどれも親が無かったので、`--pid=$$` を付けていれば終わっていたはず）
- [済] Monitor の見張りで `tail -f --pid=$$` なら残らないことを確かめる（2026-10-11。同じ形の見張りを 2 本立て、1 行ずつ知らせが届くのを見てから TaskStop で止めた。`--pid` なしは tail と grep が残り、`--pid=$$` ありは何も残らなかった。Monitor が立てる bash は Windows 上で 2 段（`bin/bash.exe` → `usr/bin/bash.exe`）。tail と grep の Windows 上の親は、起動の直後から無いプロセスになっている）
- [済] 共通ルールへ上げる（2026-10-12。「シェル実行ルール」＞「見張りの tail には --pid を付ける」を足した。ローカルルールの tail の行は共通ルールへの参照に置き換え、試験が無い日も区切りで `psls tail` を流す行を足した。きっかけは 10/04 から 8 日間残っていた `tail -F` の 1 本で、10/11 の片付けでは `-F`（大文字）を見落としていた）
