llama.cpp・エージェント・Node.js を最新にして、これまでの試験をやり直す。版が上がると結果が変わりうるため、閉域網へ持っていく前に、持っていく版で結果を取り直す。

- [済] llama.cpp を b10612 から b11320（CUDA 12.4 版）にする。前の版は `bin\llama.cpp-b10612` に残した
- [済] Pi を 0.87.1 → 0.99.2、Codex CLI を 0.158.0 → 0.159.3、OpenCode を 1.18.33 → 1.18.34 にする（Claude Code 2.1.286・Aider 0.86.2 は最新のまま）。llama.cpp は日に何十もビルドが出るため b11320 で止める
- [済] Node.js を v26.8.1 → v26.10.0 にする（利用者が msi を実行した。インストール先は `C:\Tools\nodejs`）
- [済] 試験スクリプトが結果ファイルに版を書き込むようにする
- [済] 画面表示の出力先を確かめる（内蔵 GPU が出していた。VRAM の空きは nvidia-smi で 3962 MiB で、前回の再測定と同じ。llama.cpp の `--list-devices` は CUDA から見た値で 3287 MiB と出るため、比べるときは同じ測り方にそろえる）
- [済] E4B で 4 エージェントに日本語の確認と sum を流し、壊れていないことを確かめる（日本語は 4 つとも合格。sum は Claude Code・Pi・OpenCode が合格、Aider は実行したが結果を答えず、前回と同じ傾向）
- [済] 主な速度を llama-bench で新旧を交互に測る（pp512・tg64。Qwen3-4B・E4B・Qwen3-30B-A3B は誤差の範囲。gpt-oss-20b の pp512 だけ 138 → 128 tok/s と約 7% 遅い。記録は `logs/bench-versions-20261001.txt`）
- [済] sum の残り 18 本 × 4 エージェントをやり直し、前の版と比べて資料に反映する（1 セット目は Claude Code 12/19・Pi 15/19。前回の 16・14 との差が揺れか版の影響かを見るため、`tools/50_run/run-sum-sets.ps1` で 3 セット以上流す）
- [済] 3 セットの表を仕上げる（OpenCode の 3 セット目と Devstral を入れ、合格数を数え直し、サイズ順にしてモデルの横に x.xGB を書く。`sum-table.ps1 -Sets` で結果のファイルから作るようにした）
- [済] 実行の跡が無い合格を ☑️補欠合格 として表と判定（`sum-table.ps1`）に入れる（判定は `sum-judge.ps1` の `Get-SumMark`・`Format-SumCell`。テスト 36 件）
- [済] NVIDIA GPU で 10 分以内に終わった 55 組を、Intel GPU（Vulkan 版・30 分）と NVIDIA GPU（4 回目・10 分）で流し、10 分で ⏱️ があった 6 組を 40 分で流し直して、試験結果に書く（判定は標準出力だけで見るように直した。`tools/50_run/run-sum-matrix.ps1`）
- [済] Aider に別の指示で実行させた結果と、CPU だけで流した結果を試験結果に書く（「Aider に別の指示で実行させた結果」「CPU で流した結果」「調査結果のまとめ」）
- [済] 時間切れの既定を、NVIDIA GPU 10 分・Intel GPU 15 分、名前に Thinking・Reasoning が入るモデルはその倍にする（`run-sum-matrix.ps1`・`test-agents.ps1`・`test-cc-tools.ps1`。決め方は試験結果の「これからの時間切れの決め方」。`paths.ps1` の `Get-LlmTimeout` にまとめ、`-TimeoutSec` を渡せばそちらを使う。CPU 版は Intel GPU と同じ 15 分。テスト `tests/paths.tests.ps1`）
- [済] 読み書きの試験をやり直す（2026-10-05。前の版で両方合格の 16 本のうち 15 本が今回も合格。試験結果の「版を上げて流し直した結果」）
