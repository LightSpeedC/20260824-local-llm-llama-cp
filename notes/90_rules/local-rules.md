## 1. 長い試験・測定の進め方

適用条件: 試験・測定・ダウンロードなど、数十分以上かかる処理を流すとき。

- **結果は1件終わるごとに、その場で応答に書く**。まとめて最後に報告しない
- **途中の進み具合も報告する**。1時間以上結果が出ないときは、いま何件目か・どこまで進んだかを伝える
- **見張りは Monitor で仕掛ける**。試験の出力ファイルは終わるまで書き出されないことがあるので、`logs/` に1件ずつできる結果ファイルを見る
- **試験が終わったら、残ったプロセスを確かめてから結果を報告する**。`psls tail`・`psls grep`・`psls llama-server`・`psls aider` で見る
- **止めるのは、このプロジェクトのものと見分けられた分だけ**。先祖のプロセスが残っていればそれで、残っていなければコマンドラインに含まれるプロジェクトのパス・出力先で見分ける。止めるときは `taskkill /PID <pid> /T /F`
- **見張りの tail は、共通ルール「シェル実行ルール」＞「見張りの tail には --pid を付ける」に従う**
- **試験が無い日も、区切りで `psls tail` を流して確かめる**。`--pid` を付け忘れた分を拾うため

理由: Claude Code の試験は1問に最長15〜30分かかり、全部で数時間になる。途中が見えないと、止めるか続けるかを判断できない。

## 2. AIエージェントの特徴を保つ

適用条件: エージェントの版を上げるとき、新しいエージェントを試すとき、試験の起動のしかたを変えるとき、試験でエージェントの動きに気づいたとき。

- **起動のしかたで結果が変わるエージェントの特徴は、i261014-01「AIエージェントの特徴」に書く**
- **版を上げたら、その資料の特徴が今も当てはまるかを見る**。当てはまらなくなったら、資料を直す
- **新しい特徴を見つけたら、その場で資料に足す**。どの版で、どの条件で、何を確かめたかを書き、確かめていないことは「確かめていない」と書く
- **特徴に合わせて入れた回避策は、資料を読んで外してよいと決めるまで外さない**。いまは `paths.ps1` が環境変数 `PWD` を外している。外すと OpenCode が、作業用のコピーではなくプロジェクトの root に書く
- **同じ型の不合格が、モデルを替えても続くときは、モデルの力を疑う前に、起動のしかた（環境変数・作業フォルダ）を疑う**。OpenCode の `PWD` で 26 組が無駄になった

## 3. commit・push

適用条件: このプロジェクトで commit・push するとき。

- **commit・push は、利用者に確かめずに行う**。共通ルール「重大な操作の確認方法」の例外
- **対象は、このプロジェクトのすべてのファイル**
- **載せるファイルは、自分が変えたものを名指しする**。`git add -A` ・ `git add .` ・ `git commit -a` は使わない (共通ルールのまま)
- **区切りごとに、適切な単位に分けて commit する**
- **確かめずに行うのは、commit と push だけ**。`git reset` ・ 履歴の書き換え (`--amend` ・ `--force`) は、共通ルールどおり、説明して確認を取る
