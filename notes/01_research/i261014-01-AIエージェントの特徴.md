## 1. 分かったこと

最新の版で試験をやり直したとき（[i261014-01](../40_issues/issues.md)）、OpenCode 1.19.0 の sum が 26 組すべて「作成なし」になった。 モデルは `sum.js` を作り、`node sum.js` で 55 も出していた。**書いた先が、試験用の作業フォルダではなく、プロジェクトの root だった**。

- **OpenCode 1.19.0 は、書くファイルの置き場を、実際の作業フォルダではなく環境変数 `PWD` で決める**（実験 2・3・5）
- **Bash から起動すると、`PWD`（呼んだ側のフォルダ）が子に引き継がれる**。PowerShell から直接起動したときは `PWD` が無い（実験 1）
- **git のリポジトリがあるかどうかは関係しない**（実験 5・6）
- `PWD` を外して起動すると、作業フォルダに書く（実験 4・6）

## 2. OpenCode は PWD を見る

gemma-4-E4B（Q4_K_M）と llama.cpp b11609 を使い、OpenCode 1.19.0 に「`probe-xx.txt` を作れ」と頼んだ。作業フォルダは試験用のコピー（実験 5・6 だけ git のリポジトリ）。行き先は、書いた先の `filepath` と、実際にできたファイルで確かめた。凡例: ✅ 作業フォルダに書いた ／ ❌ 作業フォルダ以外に書いた。

| 実験 | 起動の経路 | 作業フォルダ | PWD | ファイルの行き先 |
|---|---|---|---|---|
| 1 | PowerShell から | 試験用のコピー | 無し | ✅ 作業フォルダ |
| 2 | Bash → psh | 試験用のコピー | プロジェクトの root（引き継ぎ） | ❌ プロジェクトの root |
| 3 | PowerShell から | 試験用のコピー | プロジェクトの root（自分で設定） | ❌ プロジェクトの root |
| 4 | Bash → psh | 試験用のコピー | 外した | ✅ 作業フォルダ |
| 5 | PowerShell から | git のリポジトリ | プロジェクトの root（自分で設定） | ❌ プロジェクトの root |
| 6 | PowerShell から | git のリポジトリ | 無し | ✅ 作業フォルダ |

### 作業フォルダの外に書こうとして、OpenCode に断られる組がある

- `PWD` を外したあとの流し直しで、granite-4.1-8b は `/workspace/sum.js`、Qwen3-4B-Instruct は `/sum.js` という絶対パスに書こうとした。OpenCode は「許可されていない」として断り（`The user rejected permission to use this specific tool call.`）、モデルはそのまま終わった。判定は「作成なし」になる
- この「作成なし」は、`PWD` のずれによる「作成なし」とは別のもので、モデルが作業フォルダの外のパスを選んだ結果。プロジェクトの root に `sum.js` が無いことで見分けられる
- **確かめていないこと**: 1.18.34 でも断られたか。モデルがなぜこの絶対パスを選んだか（OpenCode がモデルに渡す作業フォルダの情報によるのか、モデルの癖か）

### 確かめられなかったこと

- **OpenCode 1.18.34 も `PWD` を見ていたか**は、確かめていない。10/01〜10/02 の試験は PowerShell から流していて、`PWD` が無かった。版を上げて起きたのか、起動の経路が変わって起きたのかは、分けられていない
- **モデルなしの再現はできなかった**。`opencode debug file read` は、`PWD` を変えても作業フォルダのファイルを読めた。書き込みの道具だけが `PWD` を見ているらしい（ほかの道具は未確認）

## 3. 影響と対処

### 起きたこと

- sum の判定が「作成なし」になり、OpenCode の結果 26 組（2 セット × 13 本）が、モデルの力を測れなかった
- OpenCode が、プロジェクトの root に `sum.js` を書き続けた。**作業用のコピーに閉じ込める、という前提が破れていた**。モデルが別のファイル名を選べば、プロジェクトの本物のファイルを上書きしうる

### 対処

- `tools/50_run/paths.ps1` を読み込むときに、環境変数 `PWD` を外す。エージェントを起動するスクリプトはどれもこのファイルを読むので、1 か所で済む
- テスト `tests/paths.tests.ps1` に、「`PWD` を引き継いで起動しても、`paths.ps1` を読んだあとは空」を足した。直す前に ❌Red（実際は引き継いだ値のまま）、直したあとに ✅Green を確かめた
- 直したあと、Bash 経由（これまで落ちていた経路）で OpenCode を 1 本流し、✅ 合格（38.4 秒、作成・実行・報告・ログとも OK）を確かめた
- `PWD` を外して OpenCode を 2 セット流し直した（2026-10-15、13 本）。NVIDIA GPU で 2 回とも通ったのは、gemma-4-E4B・gemma-4-E4B-it-qat・gemma-4-12B・Bonsai-27B・Ornith-1.0-9B の 5 本。Ornith は Claude Code・Pi では不合格が多いが、OpenCode では全環境で通った。各組の結果は[試験結果](r260929-01-AIエージェントの試験結果.md)の「最新版で流し直した結果」にある

## 4. ほかのエージェントと、この資料の維持

### ほかのエージェント

- **Claude Code 2.1.299 と Pi 1.2.0 は、同じ Bash 経由の起動でも、作業フォルダに書けた**。段 2 の sum で、「作成あり」と判定された組が多数ある。`PWD` の影響は見えなかった
- **Claude Code は、ルール（利用者の `CLAUDE.md`・メモリ・フック）を読ませると、最初の要求が 2 倍以上になる**。2.1.322・2.1.325 で、ルールありは 42,806〜45,713 トークン、空のホームに向けた `-NoRules` は 17,361 トークン。E4B の読みは、ルールありで 600 秒の時間切れ、`-NoRules` で 53.9 秒の合格だった（2026-11-15、llama.cpp b12359）。試験は `-NoRules` を付けて流す。Pi・OpenCode でも同じ差が出るかは、確かめていない
- Aider・Codex CLI・Claude Code・Pi が、`PWD` 以外の環境変数や起動の経路の違いで動きを変えるかは、確かめていない

### この資料の維持

- エージェントの版を上げたとき、新しいエージェントを試すとき、試験の起動の経路を変えたときは、**この資料の特徴が今も当てはまるかを見る**
- 新しい特徴（起動のしかたで結果が変わるもの）を見つけたら、この資料に足す。どの版で、どの条件で、何を確かめたかを書き、確かめていないことは「確かめていない」と書く
- 特徴に合わせて入れた回避策（上の `PWD` を外す処理など）は、この資料を読んで外してよいかを決めるまで、外さない
