この文書の位置づけ

ローカルLLM 実行計画の Step 5 で、Claude Code を llama-server に繋いで応答が返ることは確かめた。 本書は、その先のツール（Read・Write）を実際に使えるかを、手持ちの 13 本とダウンロードした 20GB 以下の 6 本などで試した記録である。 環境は RAM 32GB・VRAM 4GB（画面表示は内蔵GPU）。

結論

共通ルールを読ませなければ、Claude Code はこのPCでも使える。 最初の試験（ルールあり）では読み・書きの両方に合格したモデルが 1 本も無かったが、 ルールを読ませず、思考を切った設定では 21 本中 15 本が 15 分以内に両方に合格した（1 時間まで待てば 16 本）。

変えたこと効果
共通ルールを読ませない（空のホーム）最初に送る量が約 60,000 → 17,000〜23,600 トークン。1 往復が数分から数十秒になり、ツールを呼ぶようになった
思考を切る（--reasoning off）思考を長く出して時間切れになるのを防ぐ
チャットテンプレートの差し替え途中の system で 500 エラーになる 4 本（Ministral 2 本・Bonsai・Qwen3.5-9B）が通るようになった
ホームと作業フォルダをプロジェクトの外に置くQwen 系がプロジェクトのパスを推測して外に書きにいくのを防ぐ（第 3 章）

使える設定

gemma-4-E2B-it を例にする。ほかのモデルも -m と --alias を替えるだけでよい（差し替えたテンプレートがあるモデルは --chat-template-file を足す）。

llama-server

"bin\llama.cpp\llama-server.exe" ^
  -m "C:\AI_Models\Gemma\gemma-4-E2B-it-GGUF\gemma-4-E2B-it-Q4_K_M.gguf" ^
  -c 65536 -np 1 -ngl 99 ^
  -nkvo -ctk q8_0 -ctv q8_0 -fa on ^
  --reasoning off ^
  --alias gemma-4-E2B-it-Q4_K_M ^
  --host 127.0.0.1 --port 8080

3.2 GB を超えるモデルは -ngl を渡さず、llama-server の自動配置に任せた。テンプレートは tools/50_run/templates/ にある。

Claude Code

環境変数値
ANTHROPIC_BASE_URLhttp://127.0.0.1:8080
ANTHROPIC_AUTH_TOKEN任意の文字列（llama-server は確かめない）
ANTHROPIC_MODEL・ANTHROPIC_SMALL_FAST_MODELサーバの --alias と同じ値
CLAUDE_CODE_MAX_CONTEXT_TOKENSサーバの -c と同じ値
API_TIMEOUT_MS1 回の要求を待つ長さ（試験では 600000〜900000）
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC1
USERPROFILE・HOMEプロジェクトの外にある空のフォルダ。共通ルール・メモリ・フックを読ませない
CLAUDE_CODE_ATTRIBUTION_HEADER0（プロジェクトの .claude/settings.json に書く）
空のホームをプロジェクトの中に置かない。 Claude Code は指示文にメモリの置き場（ホームの下）を書き込むため、そこからモデルがプロジェクトの場所を推測し、作業フォルダの外に読み書きしにいく。 試験では、ホームを W:/temp/llama-cp-home、作業フォルダを W:/temp/llama-cp-sandbox に置いて防いだ。

試験の方法と経緯

スクリプト

  • tools/50_run/test-cc.ps1 — 1 モデルを起動し、Claude Code に 1 問投げる。所要時間・ターン数・回答を logs/test-cc/ に残す
  • tools/50_run/test-cc-tools.ps1 — 10GB 未満のモデルを小さい順に 1 本ずつ起動し、読みと書きの 2 問を試す。結果は logs/test-cc-tools/ に JSON Lines で残す

どちらも環境変数（ANTHROPIC_BASE_URL ほか、root の cc1.cmd と同じもの）で接続先を切り替え、claude -p を非対話で走らせる。

サーバの設定（全モデル共通）

-c 65536 -np 1 -nkvo -ctk q8_0 -ctv q8_0 -fa on
3.2GB 以下は -ngl 99、それより大きいものは -ngl を渡さず自動配置

合否の決め方

問質問合格
読みREADME.html を Read ツールで読み、最初の h1 要素の文字列だけを答える回答に「ローカルLLM 実行環境」が入っている（読まないと分からない）
書きWrite ツールで tmp/ にファイルを作り、決めた 1 行を書くそのファイルが実際にでき、中身が一致する

1 問の待ち時間は 10 分。超えたものはタイムアウトとして記録した。

経緯

回起きたこと対処
1最初の要求を読み込んでいる途中（43,008 トークン・80 秒）で、Claude Code がメモリ不足としてコマンドを止めたプロジェクトの .claude/settings.json の env に CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1 を入れ、セッションを開き直した
2168 秒で応答が返ったが、答えが README と違い、出力も文字化けしていた出力を --output-format json でファイルに受け、UTF-8 として読むようにした
3206 秒で返ったが、質問そのものが化けていた（コマンド行に載せると CP932 になる）質問を UTF-8 のファイルにし、標準入力から渡すようにした
4質問は正しく届いた。171 秒で返ったが、ターン数 1 でツールを呼ばずに答えを作っていた（Qwen3-4B-Instruct）モデルを替える
5gpt-oss-20b（--n-cpu-moe 18）は 25 分でタイムアウト。やり取りは続いていたが、深いコンテキストで生成が 2.8 tok/s まで落ちた（短い文脈では 19 tok/s）10GB 未満の全モデルで試す（第 4 章）
613 本とも読み・書きの両方には通らない。4 本はチャットテンプレートが途中の system を例外にして 500 エラーテンプレートを取り出し、途中の system を通すように直した
7最初に送る 60,000 トークンのうち、共通ルールだけで 41,320 トークンあった（gpt-oss-20b のトークナイザで計数）USERPROFILE・HOME を空のフォルダに向け、ルールを読ませない
8ルールなしで多くが合格。思考を出すモデルは長く考えて時間切れになる--reasoning off を足す（第 5 章）
9エージェントの試験で、Aider がプロジェクトの README.html を 2 行に上書きしたgit から戻し、試験は作業用のコピーの中で動かすようにした
10作業用のコピーをリポジトリの中に置くと、Qwen 系がリポジトリの root を推測して本物に読み書きしにいった（Claude Code が作業フォルダの外として拒否）作業用のコピーをリポジトリの外（W:/temp）へ
11それでもプロジェクトのパスへ書きにいった。指示文に書かれるメモリの置き場が、プロジェクトの中の空のホームだったため空のホームも外へ移した。以後は本物を狙う呼び出しが無くなった
試験ではエージェントを本物のファイルの上で動かさない。 Aider は渡されていないファイルを「作り直してよい」と受け取ることがあり、--yes-always を付けると確認なしで上書きする。 コードは git から戻せても、コミット前の変更は戻らない。

分かったこと

  • 「応答が返る」と「ツールを使える」は別。Qwen3-4B-Instruct の読みは 1 ターンで終わっており、ファイルを読まずにもっともらしい答えを作った。ターン数と、答えが本物かの両方を見ないと判別できない
  • チャットテンプレートで落ちるモデルが 4 本ある（Ministral 2 本・Bonsai・Qwen3.5-9B）。モデル側の問題か、llama-server のテンプレート処理の問題かは切り分けていない
  • 時間切れのうち 3 本は、実際にはツールを使えていた。ファイルができた後に何をしていたかは記録していない
時間切れは「使えない」ではない。 10 分を超えたものは今回の条件で打ち切っただけで、待てば終わるかどうかは確かめていない。 テンプレートのエラーも、テンプレートを差し替えれば通る可能性がある。

ルールなし・思考なしの結果

Pi・OpenCode・Aider で試した結果

Claude Code（ルールなし）で時間切れになった 3 本を、別のエージェントで試した。サーバの設定は第 5 章と同じ。 質問はコマンド行に載せるため英語にした。スクリプトは tools/50_run/test-agents.ps1。
