## この文書の位置づけ

[ローカルLLM 実行計画](../10_plan/p260824-01-ローカルLLM実行計画.md)の Step 5 で、Claude Code を llama-server に繋いで応答が返ることは確かめた。 本書は、その先の**ツール（Read・Write）を実際に使えるか**を、手持ちの 13 本とダウンロードした 20GB 以下の 6 本などで試した記録である。 環境は RAM 32GB・VRAM 4GB（画面表示は内蔵GPU）。

## 1. 結論

**共通ルールを読ませなければ、Claude Code はこのPCでも使える。** 最初の試験（ルールあり）では読み・書きの両方に合格したモデルが 1 本も無かったが、 ルールを読ませず、思考を切った設定では **20 本中 15 本**が 15 分以内に両方に合格した（1 時間まで待てば 16 本）。

| 変えたこと | 効果 |
|---|---|
| 共通ルールを読ませない（空のホーム） | 最初に送る量が約 60,000 → 17,000〜23,600 トークン。1 往復が数分から数十秒になり、ツールを呼ぶようになった |
| 思考を切る（`--reasoning off`） | 思考を長く出して時間切れになるのを防ぐ |
| チャットテンプレートの差し替え | 途中の system で 500 エラーになる 4 本（Ministral 2 本・Bonsai・Qwen3.5-9B）が通るようになった |
| ホームと作業フォルダをプロジェクトの外に置く | Qwen 系がプロジェクトのパスを推測して外に書きにいくのを防ぐ（第 3 章） |

### 速く使えるモデル

| モデル | サイズ | 読み | 書き |
|---|---:|---:|---:|
| gemma-4-E2B-it | 3.19 GB | 13 秒 | 10 秒 |
| gemma-4-E4B-it | 4.97 GB | 38 秒 | 26 秒 |
| Ministral-3-3B-Instruct-2512（テンプレート差し替え） | 2.00 GB | 28 秒 | 54 秒 |

全モデルの結果は第 5 章。Claude Code で通らなかったモデルも、Pi・OpenCode なら通るものがある（第 6 章）。

## 2. 使える設定

gemma-4-E2B-it を例にする。ほかのモデルも `-m` と `--alias` を替えるだけでよい（差し替えたテンプレートがあるモデルは `--chat-template-file` を足す）。

#### llama-server

```batch
"bin\llama.cpp\llama-server.exe" ^
  -m "C:\AI_Models\Gemma\gemma-4-E2B-it-GGUF\gemma-4-E2B-it-Q4_K_M.gguf" ^
  -c 65536 -np 1 -ngl 99 ^
  -nkvo -ctk q8_0 -ctv q8_0 -fa on ^
  --reasoning off ^
  --alias gemma-4-E2B-it-Q4_K_M ^
  --host 127.0.0.1 --port 8080
```

3.2 GB を超えるモデルは `-ngl` を渡さず、llama-server の自動配置に任せた。テンプレートは `tools/50_run/templates/` にある。

#### Claude Code

| 環境変数 | 値 |
|---|---|
| `ANTHROPIC_BASE_URL` | `http://127.0.0.1:8080` |
| `ANTHROPIC_AUTH_TOKEN` | 任意の文字列（llama-server は確かめない） |
| `ANTHROPIC_MODEL`・`ANTHROPIC_SMALL_FAST_MODEL` | サーバの `--alias` と同じ値 |
| `CLAUDE_CODE_MAX_CONTEXT_TOKENS` | サーバの `-c` と同じ値 |
| `API_TIMEOUT_MS` | 1 回の要求を待つ長さ（試験では 600000〜900000） |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | `1` |
| `USERPROFILE`・`HOME` | **プロジェクトの外にある空のフォルダ**。共通ルール・メモリ・フックを読ませない |
| `CLAUDE_CODE_ATTRIBUTION_HEADER` | `0`（プロジェクトの `.claude/settings.json` に書く） |

> [!WARNING]
> **空のホームをプロジェクトの中に置かない。** Claude Code は指示文にメモリの置き場（ホームの下）を書き込むため、そこからモデルがプロジェクトの場所を推測し、作業フォルダの外に読み書きしにいく。 試験では、ホームを `W:/temp/llama-cp-home`、作業フォルダを `W:/temp/llama-cp-sandbox` に置いて防いだ。

## 3. 試験の方法と経緯

### スクリプト

- `tools/50_run/test-cc.ps1` — 1 モデルを起動し、Claude Code に 1 問投げる。所要時間・ターン数・回答を `logs/test-cc/` に残す
- `tools/50_run/test-cc-tools.ps1` — 10GB 未満のモデルを小さい順に 1 本ずつ起動し、読みと書きの 2 問を試す。結果は `logs/test-cc-tools/` に JSON Lines で残す

どちらも環境変数（`ANTHROPIC_BASE_URL` ほか、root の `cc1.cmd` と同じもの）で接続先を切り替え、`claude -p` を非対話で走らせる。

#### サーバの設定（全モデル共通）

```text
-c 65536 -np 1 -nkvo -ctk q8_0 -ctv q8_0 -fa on
3.2GB 以下は -ngl 99、それより大きいものは -ngl を渡さず自動配置
```

#### 合否の決め方

| 問 | 質問 | 合格 |
|---|---|---|
| 読み | README.html を Read ツールで読み、最初の h1 要素の文字列だけを答える | 回答に「ローカルLLM 実行環境」が入っている（読まないと分からない） |
| 書き | Write ツールで `tmp/` にファイルを作り、決めた 1 行を書く | そのファイルが実際にでき、中身が一致する |

1 問の待ち時間は 10 分。超えたものはタイムアウトとして記録した。

### 経緯

| 回 | 起きたこと | 対処 |

| 9 | エージェントの試験で、Aider がプロジェクトの README.html を 2 行に上書きした | git から戻し、試験は作業用のコピーの中で動かすようにした |
| 10 | 作業用のコピーをリポジトリの中に置くと、Qwen 系がリポジトリの root を推測して本物に読み書きしにいった（Claude Code が作業フォルダの外として拒否） | 作業用のコピーをリポジトリの外（`W:/temp`）へ |
| 11 | それでもプロジェクトのパスへ書きにいった。指示文に書かれるメモリの置き場が、プロジェクトの中の空のホームだったため | 空のホームも外へ移した。以後は本物を狙う呼び出しが無くなった |

> [!CAUTION]
> **試験ではエージェントを本物のファイルの上で動かさない。** Aider は渡されていないファイルを「作り直してよい」と受け取ることがあり、`--yes-always` を付けると確認なしで上書きする。 コードは git から戻せても、コミット前の変更は戻らない。

### 分かったこと

- **「応答が返る」と「ツールを使える」は別**。Qwen3-4B-Instruct の読みは 1 ターンで終わっており、ファイルを読まずにもっともらしい答えを作った。ターン数と、答えが本物かの両方を見ないと判別できない
- **チャットテンプレートで落ちるモデルが 4 本ある**（Ministral 2 本・Bonsai・Qwen3.5-9B）。モデル側の問題か、llama-server のテンプレート処理の問題かは切り分けていない
- **時間切れのうち 3 本は、実際にはツールを使えていた**。ファイルができた後に何をしていたかは記録していない

> [!IMPORTANT]
> **時間切れは「使えない」ではない。** この章の時点では、10 分を超えたものを打ち切っただけだった。 その後、ルールを読ませない設定と 1 時間の枠で試し直し、テンプレートのエラーも差し替えで解消した（第 5 章）。

## 6. Pi・OpenCode・Aider・Codex で試した結果

Claude Code（ルールなし）で時間切れになった 3 本を、別のエージェントで試した。サーバの設定は第 5 章と同じ。 質問はコマンド行に載せるため英語にした。スクリプトは `tools/50_run/test-agents.ps1`。

| モデル | Pi | OpenCode | Aider |
|---|---|---|---|
| NVIDIA-Nemotron-3-Nano-4B | ✅ **両方合格** 読み 18 秒・書き 19 秒 | ✅ **両方合格** 読み 431 秒・書き 58 秒 | ⚠ **書きのみ** 書き 11 秒 |
| GLM-4.6V-Flash | ❌ **不可** 読みは時間切れ、書きは作ったと答えたがファイルなし | ⚠ **書きのみ** 書き 152 秒 | ⚠ **書きのみ** 書き 16 秒 |
| Qwen3-4B-Thinking-2507 | ✅ **両方合格** 読み 145 秒・書き 88 秒 | **時間切れ** | ⚠ **書きのみ** 書き 311 秒 |

- **Pi がいちばん速い**。Nemotron は Claude Code では 1 時間の枠でも読み書きしなかったが、Pi では 18 秒で答えた
- **Aider はファイルを先に渡して使う道具**。ファイルを渡さずに「読め」と頼むと、読めないと答えるか、中身を作り上げる。書きは 3 本とも通った（送る量は約 650 トークン）
- 合うエージェントはモデルによって違う。同じモデルでも Pi と OpenCode で結果が逆になった

### Codex CLI（ルールなし）

`CODEX_HOME` を空のフォルダに向け、利用者の設定と `AGENTS.md` を読ませずに試した（2026-09-30）。 接続は `config.toml` の `[model_providers.*]` に `wire_api = "responses"` で書いた。

| モデル | 読み | 書き | 備考 |
|---|---|---|---|
| gpt-oss-20b | ✅ **53 秒** | ✅ **128 秒** |  |
| gemma-4-E2B-it | ❌ **不可** | ✅ **7 秒** | 読みは「これから読む」と答えたところで終わった |

> [!WARNING]
> **Windows では安全装置を外さないと動かない。** Codex はファイルの読み書きに PowerShell のコマンドを使う。`-s workspace-write` ではそのコマンドが policy で止められ（`rejected: blocked by policy`）、読みも書きもできなかった。 試験は `--dangerously-bypass-approvals-and-sandbox` を付け、作業フォルダを `W:/temp` の下のコピーにして利用者が実行した。安全装置が無いので、モデルは作業フォルダの外にも手を出せる。
