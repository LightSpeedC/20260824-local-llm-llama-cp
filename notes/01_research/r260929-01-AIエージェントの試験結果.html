この文書の位置づけ

ローカルLLM 実行計画の Step 5 で、Claude Code を llama-server に繋いで応答が返ることは確かめた。 本書は、その先のツール（Read・Write）を実際に使えるかを、手持ちの 14 本とダウンロードした 6 本の計 20 本で試した結果である。 環境は RAM 32GB・VRAM 4GB（画面表示は内蔵GPU）。

試験は 2 問。README.html を読んで最初の h1 を答える（読み）と、決めた 1 行をファイルに書く（書き）で、表の秒数はエージェントが終わるまでの時間。 試し方・途中で起きたこと・流したすべての試験は試験の経緯と全実行の記録、 設定の中身と動かし方は使う・試す手順にある。

結論

共通ルールを読ませず、思考を切れば、Claude Code はこのPCでも使える。 20 本中 15 本が 15 分以内に読み・書きの両方に合格した（1 時間まで待てば 16 本）。

どのエージェントを使うか

エージェント評価根拠
Claude Code（ルールなし）推奨20 本すべてで試したのはこれだけで、15 本が 15 分以内に合格した。日本語で「プログラムを書いて実行する」問でも、19 本中 16 本が合格していちばん多い（第 4 章）。設定は cc1.cmd に入っている
Pi速さ重視合格した問は、どれも Claude Code より速い。gemma-4-E4B は読み 13 秒・書き 13 秒、gpt-oss-20b は 30 秒・21 秒で、Claude Code の 2〜3 倍速い。Nemotron は Claude Code では不可、Pi では 18 秒。ただし gemma-4-E2B の読みは 3 回中 1 回しか答えなかった（第 3 章）。プログラムを書いて実行する問は 19 本中 14 本が合格し、合格はどれも 2 分以内（第 4 章）
OpenCode遅いNemotron は合格したが、読みに 431 秒かかった。プログラムを書いて実行する問は 19 本中 9 本（第 4 章）
Codex CLI勧めない合格は gpt-oss-20b だけ。Windows では安全装置を外さないとファイルを読み書きできない
Aider勧めないファイルを先に渡して使う道具で、読みの問が成り立たない。試験中にプロジェクトの README.html を上書きした。プログラムは 19 本とも書けたが、自分では実行しない（第 4 章）
ルールなしの Claude Code には、利用者の決めごとが効かない。 cc1.cmd はホームを空のフォルダに替えるため、共通ルール（commit を勝手にしない等）もメモリも読まない。

  • 合うエージェントはモデルによって違う。同じモデルでも Pi と OpenCode で結果が逆になった

Codex CLI（ルールなし）

CODEX_HOME を空のフォルダに向け、利用者の設定と AGENTS.md を読ませずに試した（2026-09-30）。 接続は config.toml の [model_providers.*] に wire_api = "responses" で書いた。

モデル読み書き備考
gpt-oss-20b53 秒128 秒
gemma-4-E2B-it不可7 秒読みは「これから読む」と答えたところで終わった
Windows では安全装置を外さないと動かない。 Codex はファイルの読み書きに PowerShell のコマンドを使う。-s workspace-write ではそのコマンドが policy で止められ（rejected: blocked by policy）、読みも書きもできなかった。 試験は --dangerously-bypass-approvals-and-sandbox を付け、作業フォルダを W:/temp の下のコピーにして利用者が実行した。安全装置が無いので、モデルは作業フォルダの外にも手を出せる。

効いた設定とその理由

最初の試験（共通ルールを読ませた状態）では、読み・書きの両方に合格したモデルは 1 本も無かった。 次の 4 つを変えて、第 2 章の結果になった。引数と環境変数の中身は使う・試す手順にある。

変えたこと効果
共通ルールを読ませない（空のホーム）最初に送る量が約 60,000 → 17,000〜23,600 トークン（共通ルールだけで 41,320 トークンあった）。1 往復が数分から数十秒になり、ツールを呼ぶようになった
思考を切る（--reasoning off）思考を長く出して時間切れになるのを防ぐ
チャットテンプレートの差し替えClaude Code は会話の途中にも system を送る。それを例外にして 500 エラーを返していた 4 本（Ministral 2 本・Bonsai・Qwen3.5-9B）が通るようになった
ホームと作業フォルダをプロジェクトの外に置くモデルがプロジェクトの場所を推測し、本物のファイルに読み書きしにいくのを防ぐ。Claude Code は指示文にメモリの置き場（ホームの下）を書くため、ホームがプロジェクトの中にあると場所が知られる
