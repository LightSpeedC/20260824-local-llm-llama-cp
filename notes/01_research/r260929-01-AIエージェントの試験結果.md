## この文書の位置づけ

[ローカルLLM 実行計画](../10_plan/p260824-01-ローカルLLM実行計画.md)の Step 5 で、Claude Code を llama-server に繋いで応答が返ることは確かめた。 本書は、その先の**ツール（Read・Write）を実際に使えるか**を、手持ちの 14 本とダウンロードした 6 本の計 20 本で試した結果である。 環境は RAM 32GB・VRAM 4GB（画面表示は内蔵GPU）。

試験は 2 問。README.html を読んで最初の h1 を答える（読み）と、決めた 1 行をファイルに書く（書き）で、表の秒数はエージェントが終わるまでの時間。 試し方・途中で起きたこと・流したすべての試験は[試験の経緯と全実行の記録](r260930-01-エージェント試験の経緯と全実行の記録.md)、 設定の中身と動かし方は[使う・試す手順](../10_plan/p260930-01-ClaudeCodeを使う試す手順.md)にある。

## 1. 結論

**共通ルールを読ませず、思考を切れば、Claude Code はこのPCでも使える。** 20 本中 15 本が 15 分以内に読み・書きの両方に合格した（1 時間まで待てば 16 本）。

### どのモデルを使うか

| 用途 | モデル | サイズ | 読み | 書き | 備考 |
|---|---|---:|---:|---:|---|
| 普段使い | **gemma-4-E4B-it** | 4.97 GB | 38 秒 | 26 秒 | いまの `cc1.cmd` の既定。実行計画でも、知識を問う用途に採っている |
| 速さ最優先 | **gemma-4-E2B-it** | 3.19 GB | 13 秒 | 10 秒 | 最速。全層が GPU に載る（`-ngl 99`） |
| 大きいモデルが要るとき | **gpt-oss-20b** | 11.28 GB | 84 秒 | 40 秒 | 生成は 19 tok/s（実行計画の 32GB での再測定）。Codex CLI でも合格した |
| 最小 | Ministral-3-3B-Instruct-2512 | 2.00 GB | 28 秒 | 54 秒 | チャットテンプレートの差し替えが要る |

20GB 級の MoE も合格したが、読みに 127〜203 秒かかる（第 2 章）。

### どのエージェントを使うか

| エージェント | 評価 | 根拠 |
|---|---|---|
| Claude Code（ルールなし） | ✅ **推奨** | 20 本すべてで試したのはこれだけで、15 本が 15 分以内に合格した。日本語で「プログラムを書いて実行する」問でも、19 本中 16 本が合格していちばん多い（第 4 章）。設定は `cc1.cmd` に入っている |
| Pi | ✅ **速さ重視** | 合格した問は、どれも Claude Code より速い。gemma-4-E4B は読み 13 秒・書き 13 秒、gpt-oss-20b は 30 秒・21 秒で、Claude Code の 2〜3 倍速い。Nemotron は Claude Code では不可、Pi では 18 秒。ただし gemma-4-E2B の読みは 3 回中 1 回しか答えなかった（第 3 章）。プログラムを書いて実行する問は 19 本中 14 本が合格し、合格はどれも 2 分以内（第 4 章） |
| OpenCode | ⚠️ **遅い** | Nemotron は合格したが、読みに 431 秒かかった。プログラムを書いて実行する問は 19 本中 9 本（第 4 章） |
| Codex CLI | ❌ **勧めない** | 合格は gpt-oss-20b だけ。Windows では安全装置を外さないとファイルを読み書きできない |
| Aider | ❌ **勧めない** | ファイルを先に渡して使う道具で、読みの問が成り立たない。試験中にプロジェクトの README.html を上書きした。プログラムは 19 本とも書けたが、自分では実行しない（第 4 章） |

> [!WARNING]
> **ルールなしの Claude Code には、利用者の決めごとが効かない。** `cc1.cmd` はホームを空のフォルダに替えるため、共通ルール（commit を勝手にしない等）もメモリも読まない。

## 3. エージェント別の結果

Claude Code（ルールなし）で通らなかった 3 本を、別のエージェントで試した。サーバの設定は第 2 章と同じ。 質問はコマンド行に載せるため英語にした。

| モデル | Pi | OpenCode | Aider |
|---|---|---|---|
| NVIDIA-Nemotron-3-Nano-4B | ✅ **両方合格** 読み 18 秒・書き 19 秒 | ✅ **両方合格** 読み 431 秒・書き 58 秒 | ⚠️ **書きのみ** 書き 11 秒 |
| GLM-4.6V-Flash | ❌ **不可** 読みは時間切れ、書きは作ったと答えたがファイルなし | ⚠️ **書きのみ** 書き 152 秒 | ⚠️ **書きのみ** 書き 16 秒 |
| Qwen3-4B-Thinking-2507 | ✅ **両方合格** 読み 145 秒・書き 88 秒 | ⬜ **時間切れ** | ⚠️ **書きのみ** 書き 311 秒 |

- **Pi がいちばん速い**。Nemotron は Claude Code では 1 時間の枠でも読み書きしなかったが、Pi では 18 秒で答えた
- **Aider はファイルを先に渡して使う道具**。ファイルを渡さずに「読め」と頼むと、読めないと答えるか、中身を作り上げる。書きは 3 本とも通った（送る量は約 650 トークン）
- 合うエージェントはモデルによって違う。同じモデルでも Pi と OpenCode で結果が逆になった

### 速いモデルを Pi で

第 1 章で選んだ速い 3 本を、Pi でも試した（2026-09-30）。サーバの設定は第 2 章と同じ。E2B は結果が揺れたので 3 回流した。

| モデル | Pi 読み | Pi 書き | Claude Code 読み | Claude Code 書き |
|---|---|---|---:|---:|
| gemma-4-E2B-it | ⚠️ **3 回中 1 回** 4 秒 | ✅ **3 秒** | 13 秒 | 10 秒 |
| gemma-4-E4B-it | ✅ **13 秒** | ✅ **13 秒** | 38 秒 | 26 秒 |
| gpt-oss-20b | ✅ **30 秒** | ✅ **21 秒** | 84 秒 | 40 秒 |

- **E4B と gpt-oss-20b は、Pi のほうが 2〜3 倍速い**
- E2B の読みは、不合格の 2 回とも答えが空だった。ファイルの中身を受け取った直後に 1 トークンで生成を終え、答えを書かない。書きは 3 回ともファイルができた

### Codex CLI（ルールなし）

`CODEX_HOME` を空のフォルダに向け、利用者の設定と `AGENTS.md` を読ませずに試した（2026-09-30）。 接続は `config.toml` の `[model_providers.*]` に `wire_api = "responses"` で書いた。

| モデル | 読み | 書き | 備考 |
|---|---|---|---|
| gpt-oss-20b | ✅ **53 秒** | ✅ **128 秒** |  |
| gemma-4-E2B-it | ❌ **不可** | ✅ **7 秒** | 読みは「これから読む」と答えたところで終わった |

> [!WARNING]
> **Windows では安全装置を外さないと動かない。** Codex はファイルの読み書きに PowerShell のコマンドを使う。`-s workspace-write` ではそのコマンドが policy で止められ（`rejected: blocked by policy`）、読みも書きもできなかった。 試験は `--dangerously-bypass-approvals-and-sandbox` を付け、作業フォルダを `W:/temp` の下のコピーにして利用者が実行した。安全装置が無いので、モデルは作業フォルダの外にも手を出せる。

## 4. 日本語でプログラムを書かせた結果

書きの試験に 10 分以内で合格した 19 本を、4 つのエージェントで試した（2026-09-30〜10-01）。問は日本語のまま渡した。

```text
1から10までの合計を表示するnode.jsプログラムをsum.jsに書く。node sumで実行する
```

- 1 組 1 回ずつなので、NVIDIA GPU と結果が違う組（Qwen3-4B-Instruct の OpenCode が ❌、GLM-4.6V の OpenCode が ✅ など）は、揺れの範囲を出ない

> [!IMPORTANT]
> **2026-10-04 に流した前回の結果は捨てた。** この PC では Vulkan 版から Intel と NVIDIA の両方が見え、前回は NVIDIA にも一部が載っていた（12B-QAT で 49 層中 12 層が NVIDIA、残りは CPU）。Intel だけの速さにならないため、この表で置き換えた。 Intel に全部載せると、12B-QAT のプロンプトの処理は 68.8 tok/s で CPU 版（14.8 tok/s）の 4.6 倍、生成は 3.4 tok/s で CPU 版（3.8 tok/s）とほぼ同じ。

### 調査結果のまとめ

NVIDIA GPU・Intel GPU・CPU で流した結果をまとめる。

| 環境 | 向くエージェント | 勧めるモデル | 根拠 |
|---|---|---|---|
| NVIDIA GPU | Claude Code・Pi | gemma-4-E4B・gemma-4-26B-A4B | この 2 本は 3 つのエージェントで 4 回とも ✅。通る本数は Claude Code、速さは Pi が上 |
| Intel GPU | Pi | gemma-4-E4B・gemma-4-12B-QAT | この 2 本は 3 つのエージェントとも ✅。Pi なら 2 分以内（E4B 29 秒、12B-QAT 88 秒）。Claude Code は 5〜15 分かかる。11GB を超えるモデルは使えない |
| CPU | Pi | gemma-4-E4B・gemma-4-E2B・Qwen3.5-9B | Pi は 1 分前後で通る。Claude Code・OpenCode はほとんど時間切れ |

- **gemma-4-E4B は、NVIDIA GPU・Intel GPU・CPU のどれでも、3 つのエージェントすべてで合格した**。どの環境でもまず試すモデルになる
- **合否はモデルとエージェントの組で決まり、GPU の種類ではほとんど変わらない**。変わるのは速さで、最初に送る量が多い Claude Code ほど遅い環境の影響を強く受ける。Intel GPU と CPU では、大きいモデルは時間切れになって使えない
- **同じ組でも結果は揺れる**。1 回だけの合否で組を決めず、複数回流して確かめる
- **☑️（実行せずに答える）はモデルの癖**。gpt-oss-20b・Qwen3-30B-A3B・Ministral-3-14B-Reasoning は、どの環境・エージェントでも ☑️ が多い
- **時間切れは、NVIDIA GPU で 10 分、Intel GPU と CPU で 15 分、名前に Thinking・Reasoning が入るモデルは倍**。延ばしても通る組はほとんど増えない

## 5. 効いた設定とその理由

最初の試験（共通ルールを読ませた状態）では、読み・書きの両方に合格したモデルは 1 本も無かった。 次の 4 つを変えて、第 2 章の結果になった。引数と環境変数の中身は[使う・試す手順](../10_plan/p260930-01-ClaudeCodeを使う試す手順.md)にある。

| 変えたこと | 効果 |
|---|---|
| 共通ルールを読ませない（空のホーム） | 最初に送る量が約 60,000 → 17,000〜23,600 トークン（共通ルールだけで 41,320 トークンあった）。1 往復が数分から数十秒になり、ツールを呼ぶようになった |
| 思考を切る（`--reasoning off`） | 思考を長く出して時間切れになるのを防ぐ |
| チャットテンプレートの差し替え | Claude Code は会話の途中にも system を送る。それを例外にして 500 エラーを返していた 4 本（Ministral 2 本・Bonsai・Qwen3.5-9B）が通るようになった |
| ホームと作業フォルダをプロジェクトの外に置く | モデルがプロジェクトの場所を推測し、本物のファイルに読み書きしにいくのを防ぐ。Claude Code は指示文にメモリの置き場（ホームの下）を書くため、ホームがプロジェクトの中にあると場所が知られる |

## 6. 未確認のこと

- **Pi で試したのは 6 本だけ**。20GB 級の MoE や、Claude Code で遅かったモデルを Pi で動かしたときの速さは測っていない
- Pi で gemma-4-E2B が答えを書かずに終わる理由は調べていない。Codex CLI でも、E2B の読みは「これから読む」と答えたところで終わった
- **試験は 1 ファイルを読む・1 行書く・10 行ほどのプログラムを書いて実行するだけ**。複数のファイルにまたがる編集や、大きなコードを書く作業での品質は評価していない
- **20GB 級の MoE の生成速度は、Qwen3-30B-A3B のほかは測っていない**
- Nemotron が Claude Code でだけ読み書きしない理由は調べていない。Pi・OpenCode では通る
- チャットテンプレートで 500 エラーになった 4 本が、モデル側の問題か、llama-server のテンプレート処理の問題かは切り分けていない
