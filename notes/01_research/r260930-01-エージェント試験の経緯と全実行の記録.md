## 1. 試験の方法と経緯

### スクリプト

- `tools/50_run/test-cc.ps1` — 1 モデルを起動し、Claude Code に 1 問投げる。所要時間・ターン数・回答を `logs/test-cc/` に残す
- `tools/50_run/test-cc-tools.ps1` — モデルを小さい順（`-Only` を渡したときは書いた順）に 1 本ずつ起動し、Claude Code で読みと書きの 2 問を試す。結果は `logs/test-cc-tools/` に JSON Lines で残す
- `tools/50_run/test-agents.ps1` — 同じ 2 問を Pi・OpenCode・Aider・Codex CLI で試す。質問はコマンド行に載せるため英語にした。結果は `logs/test-agents/`

Claude Code は環境変数（`ANTHROPIC_BASE_URL` ほか、root の `cc1.cmd` と同じもの）で接続先を切り替え、`claude -p` を非対話で走らせる。 経緯の 10 より後は、どのエージェントもリポジトリの外に置いた作業用のコピー（`W:/temp/llama-cp-sandbox`）の中で動かし、コピーは 1 問ごとに作り直した。

#### サーバの設定（全モデル共通）

```text
-c 65536 -np 1 -nkvo -ctk q8_0 -ctv q8_0 -fa on
3.2GB 以下は -ngl 99、それより大きいものは -ngl を渡さず自動配置
```

#### 合否の決め方

| 問 | 質問 | 合格 |
|---|---|---|
| 読み | README.html を Read ツールで読み、最初の h1 要素の文字列だけを答える | 回答に「ローカルLLM 実行環境」が入っている（読まないと分からない） |
| 書き | Write ツールで `tmp/` にファイルを作り、決めた 1 行を書く | そのファイルが実際にでき、中身が一致する |

1 問の待ち時間は 10〜15 分。超えたものは時間切れとして記録し、あとで 1 時間の枠で試し直した。

### 経緯

| 回 | 起きたこと | 対処 |
|---:|---|---|
| 1 | 最初の要求を読み込んでいる途中（43,008 トークン・80 秒）で、Claude Code がメモリ不足としてコマンドを止めた | プロジェクトの `.claude/settings.json` の `env` に `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1` を入れ、セッションを開き直した |
| 2 | 168 秒で応答が返ったが、答えが README と違い、出力も文字化けしていた | 出力を `--output-format json` でファイルに受け、UTF-8 として読むようにした |
| 3 | 206 秒で返ったが、質問そのものが化けていた（コマンド行に載せると CP932 になる） | 質問を UTF-8 のファイルにし、標準入力から渡すようにした |
| 4 | 質問は正しく届いた。171 秒で返ったが、ターン数 1 でツールを呼ばずに答えを作っていた（Qwen3-4B-Instruct） | モデルを替える |
| 5 | gpt-oss-20b（`--n-cpu-moe 18`）は 25 分でタイムアウト。やり取りは続いていたが、深いコンテキストで生成が 2.8 tok/s まで落ちた（短い文脈では 19 tok/s） | 10GB 未満の全モデルで試す（第 2 章） |
| 6 | 13 本とも読み・書きの両方には通らない。4 本はチャットテンプレートが途中の system を例外にして 500 エラー | テンプレートを取り出し、途中の system を通すように直した |
| 7 | 最初に送る 60,000 トークンのうち、共通ルールだけで 41,320 トークンあった（gpt-oss-20b のトークナイザで計数） | `USERPROFILE`・`HOME` を空のフォルダに向け、ルールを読ませない |
| 8 | ルールなしで多くが合格。思考を出すモデルは長く考えて時間切れになる | `--reasoning off` を足す（結果は[試験結果の第 2 章](r260929-01-AIエージェントの試験結果.md#2-モデル別の結果)） |
| 9 | Claude Code の試験が二重に走り、並行して始めたエージェントの試験とも重なった。起動に使った cmd ファイルが実行中に書き換えられたため（cmd.exe はバッチファイルを 1 行ずつ読む）。Windows では 2 つの llama-server が同じポートを取れてしまい、エラーにならずに結果が混ざった | 重なった回を無効にし、1 つずつ流し直した。長い試験は ps1 を直接呼ぶ |
| 10 | エージェントの試験で、Aider がプロジェクトの README.html を 2 行に上書きした | git から戻し、試験は作業用のコピーの中で動かすようにした |
| 11 | 作業用のコピーをリポジトリの中に置くと、Qwen 系がリポジトリの root を推測して本物に読み書きしにいった（Claude Code が作業フォルダの外として拒否） | 作業用のコピーをリポジトリの外（`W:/temp`）へ |
| 12 | それでもプロジェクトのパスへ書きにいった。指示文に書かれるメモリの置き場が、プロジェクトの中の空のホームだったため | 空のホームも外へ移した。以後は本物を狙う呼び出しが無くなった |
| 13 | Codex CLI は `-s workspace-write` では、ファイルを読み書きする PowerShell のコマンドが policy で止められた（`rejected: blocked by policy`） | `--dangerously-bypass-approvals-and-sandbox` を付け、作業用のコピーの中で利用者が実行した |

> [!CAUTION]
> **試験ではエージェントを本物のファイルの上で動かさない。** Aider は渡されていないファイルを「作り直してよい」と受け取ることがあり、`--yes-always` を付けると確認なしで上書きする。 コードは git から戻せても、コミット前の変更は戻らない。

### 分かったこと

- **「応答が返る」と「ツールを使える」は別**。Qwen3-4B-Instruct の読みは 1 ターンで終わっており、ファイルを読まずにもっともらしい答えを作った。ターン数と、答えが本物かの両方を見ないと判別できない
- **チャットテンプレートで落ちるモデルが 4 本ある**（Ministral 2 本・Bonsai・Qwen3.5-9B）。モデル側の問題か、llama-server のテンプレート処理の問題かは切り分けていない
- **時間切れのうち 3 本は、実際にはツールを使えていた**。ファイルができた後に何をしていたかは記録していない

> [!IMPORTANT]
> **時間切れは「使えない」ではない。** この章の時点では、10 分を超えたものを打ち切っただけだった。 その後、ルールを読ませない設定と 1 時間の枠で試し直し、テンプレートのエラーも差し替えで解消した（[試験結果の第 2 章](r260929-01-AIエージェントの試験結果.md#2-モデル別の結果)）。
