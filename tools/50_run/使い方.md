# start-agent の使い方

cmd から start-agent.cmd を叩き、一覧からモデルとエージェント (Claude Code・Pi・OpenCode) を選んで、llama-server と一緒に起動する

## 1. 何が使えるか

`tools/50_run/start-agent.cmd` を叩くと、`llama-server` を立て、選んだエージェントをそれに繋いで開く。エージェントを閉じると、llama-server も止まる。 モデルは `C:\AI-models` の中の gguf から、ファイル名の一部で選ぶ。

| -Agent | 起動するもの | 使い道 |
|---|---|---|
| `claude` | npm で入れた Claude Code (`claude.cmd`) | ローカルのモデルで Claude Code を使う。llama-server の Anthropic 形式の口へ直接繋ぐ |
| `claude-exe` | 単体の `bin/claude/claude.exe` | npm を使わない Claude Code (配布物の形) |
| `pi` | Pi | ローカルのモデルで Pi を使う |
| `opencode` | OpenCode | ローカルのモデルで OpenCode を使う |
| `server` | llama-server だけ | 自分で用意したクライアントから、`http://127.0.0.1:<ポート>/v1` に繋ぐ。止めるときは Ctrl+C |
| `bench` | `llama-bench` | Vulkan 版と CPU 版で、同じモデルの速さを測る (`pp512` が入力の処理、`tg64` が生成。どちらも 1 秒あたりのトークン数) |

## 2. 起動のしかた

プロジェクトのフォルダでコマンドプロンプトを開き、`-Agent` と `-Model` を渡して叩く。どちらも省ける。省くと一覧が出るので、番号で選ぶ。

### 一覧から選ぶ

```batch
tools/50_run/start-agent.cmd
```

エージェントの一覧、続けて `C:\AI-models` の gguf の一覧 (サイズと名前) が出る。番号を入れて Enter を押す。`-Agent` だけ、`-Model` だけを渡すと、省いた方だけ聞かれる。

### Claude Code

```batch
tools/50_run/start-agent.cmd -Agent claude -Model gemma-4-E4B-it-Q4_K_M
```

### Pi

```batch
tools/50_run/start-agent.cmd -Agent pi -Model gemma-4-E4B-it-Q4_K_M
```

### OpenCode

```batch
tools/50_run/start-agent.cmd -Agent opencode -Model gemma-4-E4B-it-Q4_K_M
```

### llama-server だけ

```batch
tools/50_run/start-agent.cmd -Agent server -Model gemma-4-E4B-it-Q4_K_M
```

### 速さを測る

```batch
tools/50_run/start-agent.cmd -Agent bench -Model gemma-4-E4B-it-Q4_K_M
```

終わるとき、cmd は `pause` で止まる。何かキーを押すと閉じる。

## 3. 引数

| 引数 | 必須 | 既定 | 意味 |
|---|---|---|---|
| `-Agent` | 任意 | 一覧から選ぶ | `claude`・`claude-exe`・`pi`・`opencode`・`server`・`bench` のどれか |
| `-Model` | 任意 | 一覧から選ぶ | モデルのファイル名に含まれる語 (例: `gemma-4-E4B-it-Q4_K_M`)。`C:\AI-models` の下を探し、最初に当たった gguf を使う。`mmproj` は除く。省くと、見つかった gguf を名前順に並べ、サイズと一緒に出す |
| `-Ctx` | 任意 | 65536 | 文脈の長さ (トークン) |
| `-Port` | 任意 | 0 | 0 のときは、`config.cmd` の `LLM_PORT`、無ければ環境変数 `LLM_PORT`、それも無ければ 11434 |
| `-WorkDir` | 任意 | 空 | エージェントが作業するフォルダ。空なら、`LLM_WORK_DIR` の下の `project` (未設定なら `W:\temp` の下) |

## 4. 動き方と設定

### 起動の順

1. モデルを探す。見つからなければ「モデルが見つかりません」で止まる
2. 使う llama.cpp を決める (下の「使う llama.cpp」)
3. ポートが使用中なら、使っているプログラム名を出して止まる
4. llama-server を立て、`/health` が `ok` になるまで待つ (最長 600 秒)
5. エージェントを開く。閉じたら llama-server を止め、「llama-server を止めました」と出す

### llama-server の設定

試験と同じ設定で立てる。思考なし (`--reasoning off`)、並列 1 (`-np 1`)、KV キャッシュは q8_0、Flash Attention あり、待受けは `127.0.0.1` だけ。 `tools/50_run/templates/<モデル名>.jinja` があれば、チャットテンプレートを差し替えて使う。

### 使う llama.cpp

`config.cmd` の `LLM_BACKEND` で決める。無ければ、既定の `bin/llama.cpp` (CUDA 版) を使う。

- `auto`: Vulkan のデバイスが見えれば Vulkan 版、見えなければ CPU 版
- フォルダ名を書くと固定する (例: `llama.cpp-b12359-vulkan`・`llama.cpp-b12359-cpu`)

### 設定の置き場 (config.cmd)

| 名前 | 意味 | 既定 |
|---|---|---|
| `LLM_MODEL_DIR` | モデルを探す場所 | `C:\AI-models` |
| `LLM_PORT` | llama-server のポート。`config.cmd` に無ければ、同じ名前の環境変数も読む | 11434 |
| `LLM_BACKEND` | 使う llama.cpp | `llama.cpp` |
| `LLM_WORK_DIR` | エージェントの作業・ホームを置く場所 | 未設定 (`W:\temp`) |

### エージェントの環境

- エージェントの設定・メモリは、作業用の空のホーム (`<作業の場所>\agent-home\<エージェント名>`) に置く。いつもの設定には触れない
- Node.js は、配布物の `bin/node` があればそれを先に使う。無ければ、PATH にあるものを使う
- Claude Code は、読みの待ちを 600 秒まで許す (`API_TIMEOUT_MS`)

### ログ

llama-server のログは `logs/start-agent/<日時>-<モデル名>-server.log` に書く。エージェントの画面には混ぜない。

## 5. うまく動かないとき

| 出たもの | 確かめること |
|---|---|
| 「ポート 11434 は使用中です」 | ほかのプログラム (試験・別の llama-server) が使っている。止めるか、`-Port` か `LLM_PORT` で別の番号にする |
| 「モデルが見つかりません」 | `-Model` の語が、gguf のファイル名に含まれているか。`LLM_MODEL_DIR` がモデルのある場所を指しているか |
| 「llama-server が起動しません」 | メモリが足りないことが多い。小さいモデルにする。原因は `logs/start-agent/` のログに出る |
| 「llama-server が見つかりません」 | `bin/` の下に、`LLM_BACKEND` のフォルダがあるか |
| cmd がすぐ閉じる・何も出ない | コマンドプロンプトを先に開き、そこから叩く。エラーが読める |
